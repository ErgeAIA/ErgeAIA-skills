# raster-to-svg

把图里的墨迹描成矢量轮廓，再把**交付的那个 SVG** 交给另一个渲染器渲一遍、比 IoU，证明它像。
两条铁律：产物是轮廓，不产出可编辑文字；原始矢量还在，就别描，去要源文件。

## 接不接

| 接 | 为什么 |
| --- | --- |
| 字形、标志、图标的 PNG → 要能改的 SVG | 这是本技能的正面战场 |
| 用户只给了几个字 | 用字体渲一遍再描，不要手画轮廓 |
| 要轮廓的顶点坐标或三次控制点 | 单色模式直接给 |
| 平色插画、图标 | `--colors` 分层 |
| 问"这张照片能不能转矢量" | 先答不能无损，再给替代路 |

不接：OCR、认字体、把文字还原成可编辑文本、照片级还原。**有原始矢量就停下要源文件**——
描摹已知矢量的位图，只会更差。

## 怎么跑

```bash
uv run --with numpy --with opencv-python-headless --with pillow --with resvg-py \
  python scripts/raster2svg.py -i in.png -o out --check
```

三种入口只换参数，别的不动：

| 情况 | 换什么 |
| --- | --- |
| 图 | 上面这条 |
| 只有字 | `--text "开源" --size 160`（不给 `--font` 就用系统 CJK 字体；只支持单行） |
| 平色图标 | `--colors 6` |

默认 `--mode auto` 逐条轮廓自己选折线或曲线；矩形字形用 `--mode polygon`，确实弯的笔画才上
`--mode curve`。彩色里 K 是**上界**，从能数出来的颜色数起（6-8），别从 32 起。

默认参数先跑一遍，别一上来就调。依赖两件：`pillow`（渲染器解码走它，缺了 `--check` 只剩代理值）
和渲染器（`resvg-py` 或 `rsvg-convert`，缺了标 `surrogate_metric: true`）。

## 数字怎么读

单色看三个：`components`（几个部件）、`iou_rendered`（真渲染 IoU）、`ink_ratio`（墨量比）。
彩色只看两个：`layers`、`psnr_rendered`——**彩色没有 iou，也没有墨量比**。

| 看到 | 意思 | 下一步 |
| --- | --- | --- |
| `--check` 退 0（iou ≥ 0.88，ink 0.95-1.05） | 过闸 | 交付 |
| ink < 0.95 | 墨少了 | 一次试一个：`--min-area 10` → `--close 0` → `--ss 6` |
| ink > 1.05 | 墨多了 | 一次试一个：`--error 0.8` → `--mode polygon` |
| iou 上不去、渲染器也在 | 形状没贴住 | 先看 `_check.png`（红 = 丢墨，绿 = 多墨），再按上面两行改 |
| 彩色 psnr < 30 dB | 海报化过头或不够 | 换 K；或承认这张不该走彩色路线 |

出货线是 **0.88**，不是 0.90：语料最差样本就是 0.8937，写 0.90 会否掉自己的证据。0.90 只当高精度目标。

调参只有一条协议：**一次改一个，改完重跑，把新数字报出来**。别一口气扫一串参数。

## 该停就停

| 标记 | 什么情况 | 停下来做什么 |
| --- | --- | --- |
| 🛑 | 有原始矢量（字体文件、源 SVG、设计稿导出） | 要源文件，别描 |
| 🔴 | 用户口述了字、也在意字形 | 先问用哪个字体，并说明产物是轮廓不是可编辑文本 |
| 🔴 | 第一次没过闸 | 报三个数 + 图上现象，**改一个**参数再报 |
| 🛑 | 没装渲染器（`surrogate_metric: true`） | 交 SVG，说明这个数是代理值，不能当保真度 |
| 🛑 | 用户说照片要"无损" | 不承诺无损；给三条路：留位图 / 接受海报化 / 嵌 `<image>`（嵌位图不算矢量） |

这五条是硬判据。越过任何一条，交出去的就是错答案。

## 交付什么

都写进 `--outdir`：

| 文件 | 内容 | 出现条件 |
| --- | --- | --- |
| `<name>.svg` | 每个部件一条 `<path id="cNN" fill-rule="evenodd">`（外轮廓 + 孔洞），按横向间距进 `<g id="glyph-NN">` | 总是 |
| `<name>.html` | 自包含交互报告：四视图、缩放平移、部件开关、节点叠印、坐标表 | 总是（`--no-html` 关） |
| `<name>_coords.json` / `.txt` | 逐部件的引擎、bbox、顶点+内角或三次控制点、孔洞，外加三项指标 | 仅单色 |
| `<name>_check.png` | 源图 \| 渲染 \| 差异；彩色只有前两栏 | 总是 |
| `<name>_diff.png`、`<name>_overlay.png` | 差异图 / 轮廓与节点叠图 | 仅单色 |
| `<name>_source.png` | 被描的那张字图 | 仅 `--text` |

彩色模式没有坐标表，也不分组、不给 id。用户同时要彩色和坐标，开工前就说给不了。

出口码：`0` 描完（带 `--check` 表示过闸）· `1` `--check` 没过（iou、墨量比，或无渲染器）·
`2` 工具出错（读不了输入、没轮廓、渲染器崩）。

## 底线

- 只往 `--outdir` 写，不碰用户的源图。
- 坐标表是输出，别手改它去凑指标，也别为了过闸凭空补点。
- 没有渲染器给的数，就别提"保真度"；代理值不是分数。
- 别把 vtracer 或 potrace 的分数算成自己的；也别把内部轮廓重绘当成指标——`iou_rendered` 渲的是交付的那个 SVG。
- 别把 SVG 拍平成一条 path：每个视觉部件一个 `<g id>`，孔洞靠 `evenodd` 留着。
- 别输出 `<text>`；要可编辑文字，回字体那里去。
- 别先放大源图再谈"高精度"；要放大就改 SVG 的 `width`/`height`，`viewBox` 已经是真实几何。

## 做不到什么

- **照片不能无损转矢量。** SVG 是一片片纯色，照片是连续调；`--colors` 只是海报化。要无损就留位图。
- **纯单色轮廓，potrace 更强**：同 12 个字形 0.957 vs 0.933，还快得多。用本技能，是因为 potrace 给不了
  分组可编辑的 SVG、坐标表、彩色分层，也给不了低对比墨（它固定按 0.5 阈值切，对 `#999` 灰字
  输出空文件；本版 0.94）。
- **细笔画有下限**：源图 < 2 px 的笔画描出来会断，先放大源图。
- **只认横向单行**：`--gap` 按横向间距分组，竖排、多行、旋转会分错。
- **文字密集的 UI 截图**：比 vtracer 低 1-4 dB，K=6 时文字碎成块——这类图别用本技能。
- **加 K 不等于提精度**：真实截图上 K=12 常比 K=6 更差。
- **别在矩形字形上强推 `--mode curve`**：唯一实测样本（96 px 口）从 0.93 掉到 0.52。

## 出错怎么办

症状 → 原因 → 修法在 `references/parameters.md` §故障；调参顺序在同一份的 §判据。
两条不能临场发挥：`cannot read image` → 重新定位源文件（别凭记忆重建）；`no contours found`
→ 先确认图不是空白，再降 `--min-area`。

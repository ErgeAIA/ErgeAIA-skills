# 测量契约

每维一行契约，五个字段：**测什么 / 怎么问 / 怎么判 / 报什么 / 会怎么错**。

改判分器或加题前先读本表；契约变了，`scoring.md` 与题库必须同步改。

---

## 一、数学推理（math）

| 项 | 内容 |
| --- | --- |
| 测什么 | 单步到三步的数值推理：四则、百分比、速率、比例、方程、复利、鸡兔同笼。**外加一个关键能力：识别信息不足** |
| 怎么问 | 直接给题 + 「只给出最终数值。」不要求过程，不要求 CoT。这样测的是「能否算对」，不掺「会不会写解题步骤」 |
| 怎么判 | 抽取最终数值（优先 `####`、`\boxed{}`，其次结论词之后，最后取末位数值），与标准值做相对+绝对容差比较（默认 1e-6）。分数型先遮罩再抽，避免 `1/6` 被拆成 1 和 6 |
| 报什么 | 均值 + 95% bootstrap CI；通过率（满分题占比） |
| 会怎么错 | ① 中间结果被当最终答案 ② 陷阱题（缺条件）被硬算出数 ③ 千分位/负号/分数解析错 |

**反制**：
- 最终值抽取按「结论标记之后」优先，不盲取末位数字
- 两题专门设成信息不足（math-15 缺前天数据、math-16 缺高度），正解是拒答；`gold.type = "insufficient"` 时判分只看是否拒答，不看数值
- 千分位、负号、分数在 selftest 里各有对抗用例

**这个数字不代表什么**：多步规划、形式化证明、带工具的计算。GSM8K 高分也不代表会做竞赛题。

## 二、指令遵循（ifollow）

| 项 | 内容 |
| --- | --- |
| 测什么 | 对**可程序化验证**的约束的精确遵守：长度、句数、段落数、条目数、行数、每行字数、必备词、禁词、前后缀、语言、大小写、纯数字、JSON 结构、数组类型与顺序 |
| 怎么问 | 单轮，约束写在题面里。部分题故意设「题目用词即禁词」（if-07 用「推荐」提问但禁用「推荐」）、「答案本身是数字但禁用阿拉伯数字」（if-15） |
| 怎么判 | 逐条约束判定，**部分得分** = 通过条数 / 总条数；同时记录 `all_pass`（全部通过）用于全通过率 |
| 报什么 | 均值（含部分分）+ CI；**全通过率**单独报（这才是严格口径）；通过率 |
| 会怎么错 | ① 满足一半约束就算过 ② 中英混排导致字数口径错 ③ JSON 外面包了说明文字 ④ 大小写被模型「好心」纠正 |

**反制**：
- 均值与全通过率分开报，避免「部分满足」被误读成「会遵守」
- 计字统一为「去空白后的字符数」，中英同口径，写在 `scorers.count_chars`
- JSON 判定前先剥 markdown 围栏
- if-16（三行、每行恰好五字）是最强约束题，专门抓「只满足行数不满足字数」

**这个数字不代表什么**：语气、风格、术语规避这类不可验证要求；多轮对话中的约束保持。

## 三、事实性与幻觉（factual）

| 项 | 内容 |
| --- | --- |
| 测什么 | ① 稳定事实能否答对 ② 不可回答的问题能否弃答 ③ 错误前提能否纠正 ④ 自报置信度是否校准 |
| 怎么问 | 每题后要求「回答后用一行给出『置信度: N』，N 为 0-100」 |
| 怎么判 | 三分类 + 前提类：`correct` / `incorrect` / `abstain_correct` / `over_abstain` / `hallucinated` / `premise_ok` / `premise_missed`。别名命中即算对（含数值等价）。**先判命中再判弃答**——否则「巴黎是首都，这不存在争议」会被弃答词表误伤 |
| 报什么 | 均值 + CI；**幻觉率**（incorrect + hallucinated）/ n；**弃答率**；**ECE**（5 桶期望校准误差，样本 ≥5 才算） |
| 会怎么错 | ① 弃答词表过窄漏判 ② 弃答词表过宽把正常回答误判为弃答 ③ 数值别名不匹配（38.44万 vs 384400）④ 校准样本不足却报 ECE |

**反制**：
- 弃答判定在命中判定**之后**，命中优先
- 数值别名走 `math.isclose` 而非字符串相等
- ECE 在置信度样本 < 5 时返回 `None`，报告显示「—」而不是假数字
- 四类陷阱各占一题：虚构人物论文（fact-13）、不存在标准（fact-16）、精确历史行情（fact-12）、错误前提两题（fact-14/15）

**这个数字不代表什么**：长文本事实性、时效性知识、多跳推理。题库 n=16 也不足以给出稳定的校准结论，ECE 只作趋势参考。

## 四、工具调用（tools）

| 项 | 内容 |
| --- | --- |
| 测什么 | ① 选对工具 ② 填对参数（含类型、默认值推断）③ 并行调用 ④ **无匹配工具时能否不调用**（不幻觉工具） |
| 怎么问 | 工具清单以 JSON 写进 system prompt，要求「只输出 JSON 数组，元素形如 `{"name":..., "arguments":{...}}`；无可用工具时直接说明无法完成」。**不依赖各家 function calling 模板差异**，保证跨后端可比 |
| 怎么判 | 解析调用（支持 OpenAI 对象、JSON 数组、`name(arg=val)` 三种形态）→ 查工具是否存在 → 比数量 → 逐调用配对比对参数（键集严格相等；标 `strict:false` 时只校验指定键）→ 数值字符串视为等价 |
| 报什么 | 均值 + CI；**误调用率**（spurious_call / n）；按 verdict 分布 |
| 会怎么错 | ① 参数顺序敏感 ② 多余参数未罚 ③ 数值 `"25"` 与 `25` 被判不等 ④ 应拒调时仍调用 ⑤ 输出包了说明文字 |

**反制**：
- 调用配对**与顺序无关**（remaining 列表消元）
- 严格模式下多余参数算失败（幻觉参数是真实缺陷）
- 数值统一转 float 比较
- tool-06（无翻译工具）、tool-14（只有只读工具却要删表）、tool-16（无导入工具）三题专测拒调
- tool-05（查天气 + 写建议）专测「不该调的不调」

**这个数字不代表什么**：真实 function calling 模板下的表现、多轮工具结果回填后的决策、工具返回异常时的恢复。本题库是单轮静态注入。

## 指标口径速查

| 指标 | 定义 | 注意 |
| --- | --- | --- |
| 均值 | 各题分数算术平均（含部分分） | 受部分分影响，会高于严格口径 |
| 通过率 | 满分题 / n | 严格口径 |
| 95% CI | 均值用 bootstrap 百分位法（2000 次，固定种子）；比例用 Wilson | n=16 时 CI 很宽，这是诚实的 |
| 幻觉率 | (incorrect + hallucinated) / n | 只在 factual 维 |
| 弃答率 | (abstain_correct + over_abstain) / n | 与幻觉率对读 |
| ECE | 5 桶 \|平均置信度 − 实际正确率\| 加权和 | 样本 < 5 返回 None |
| McNemar p | 配对二项精确检验 | 用于两配置比较，不用均值差 |

**为什么报 CI 而不报一位小数**：n=16 的通过率标准误约 12 个百分点。写「82.3%」是假精度，写「75%–100%」才是真信息。

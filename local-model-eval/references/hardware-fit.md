# 硬件适配评估

**定位**：独立工作流，与能力评测无依赖关系。用户问「能跑什么 / 要不要升级」时用它；只想知道「跑得怎么样」时可以完全不碰它。

**目的**：回答「这台机器能不能扛住目标配置」。答不出来时明确写「数据不足，暂不判定」，不猜。

**核心纪律**：先取证、再计算；先判断、再解释；设计服务于判断。

---

## 一、证据分级

每个关键数据必须标注为以下之一：**实测 / 规格 / 计算 / 估算 / 缺失**。

一个结论同时含多类来源时，**按最弱的一类标注**。例如容量结论里含估算法向量，整体就标「估算」，出处逐项拆开写清哪段是实测、哪段是估算——不得让实测数字替估算部分背书。

优先级：
- 负载期间的稳定读数 > 瞬时峰值 > 产品宣传值
- 引擎实际分配日志 > 引擎启动参数 > 理论公式
- 实机 `/props` / `VERSION` / `BUILD-INFO` / 能力清单 > 参考文档

不能访问用户电脑时，只能分析用户提供的日志、截图、配置；**不得假装执行过任何检测命令**。缺关键数据仍出报告，对应结论标「数据不足，暂不判定」。

### 采集项

| 部件 | 关键项 |
| --- | --- |
| GPU | 型号/架构、图形内存总量与空闲量、显存类型/位宽/数据率、持续核心与显存频率、温度/功耗/利用率、PCIe 链路 |
| CPU | 型号、核心布局、持续全核频率、温度/功耗、降频状态 |
| 系统内存 | 实际容量、可用容量、插条数、通道数、频率/数据率；必要时 NUMA |
| 带宽 | STREAM Triad 测持续系统内存带宽；CUDA bandwidthTest 区分设备内 / H2D / D2H |

条件允许时持续负载数分钟，取最后 60 秒稳定区间，并记录工具版本与测试条件。STREAM 数组必须明显超出末级缓存。

**理论带宽与复制带宽不等于 LLM 推理有效带宽**，只能作估算依据。

## 二、容量判定

### 资源预算（不得混算）

- 图形内存预算 = **当前空闲容量** − 合理余量；不能用标称总量
- 系统内存预算 = **当前可用物理内存** − 操作系统与常驻应用所需
- Windows 共享内存属于系统内存，**不是额外显存**，禁止与独显直接相加
- 统一内存架构（UMA）按共享物理池、系统预留、带宽争用单独计算
- 分页文件/交换空间 ≠ 物理内存

### 模型信息

优先读具体模型配置、权重元数据、文件大小、推理引擎日志。识别：架构、层数、参数量、量化格式、KV 头数/维度、KV 数据类型、上下文、并发、引擎版本、GPU 卸载方案。

**Q4/Q5/Q8 不是精确位宽**。优先用实际权重文件大小与引擎分配日志；否则才按参数量估算并说明误差。

**MoE 必须分开**：完整专家权重决定容量；每 Token 激活的专家权重影响读取流量与速度。**不能用激活参数量替代完整权重容量**。

### 权重、KV 与运行时开销

每个配置分别核算 GPU 与 CPU 中的权重、KV Cache、运行时缓冲/工作区及余量。优先引擎实际分配数据；缺失时明确给估算范围与假设，不能把「10%–15%」当固定事实。

标准注意力单序列 KV：

```
KV = 2 × L × H_KV × D × C × B
```

`L` 缓存层数、`H_KV` KV 头数、`D` 每头维度、`C` 实际缓存 Token 数、`B` 每元素字节数。并发序列按数量计入。各层结构或窗口长度不同时逐层求和；滑动窗口用实际缓存长度；MLA 等非标准结构按真实架构或引擎日志算，**不能硬套公式**。

GPU 与 CPU 分别核算放置位置。部分卸载优先用引擎日志；否则按真实层/张量大小搜临界点，**不得假设每层等大**。明确写出 GPU 放多少层可行、再增加时哪项资源超预算。

### 四种运行状态

矩阵维度：**模型规模 × 量化 × 上下文**。每格只能是四态之一：

| 状态 | 判据 |
| --- | --- |
| 显存内 | GPU 权重、GPU KV、运行时占用均未超图形内存预算 |
| 部分卸载 | GPU 与系统内存共同承载，双方预算满足，引擎支持该方案 |
| 仅 CPU | 权重、KV、运行时能放入系统内存；**只代表容量可行，不代表速度实用** |
| 放不下 | 所有受支持的部署方式均无法满足容量约束 |

按「显存内 → 部分卸载 → 仅 CPU → 放不下」顺序判定。每格给关键占用、可用预算、剩余余量、瓶颈。

「放不下」的格必须同时给出：上下文、部署方式、触及的资源、预计失败阶段（如权重加载时图形内存不足、KV 分配超预算、系统物理内存不足）。只能写「预计无法完成/预计超预算」，**不能写成实测崩溃**。

数据缺失时写「数据不足，暂不判定」，**不能伪装成第五种运行状态**。一格内混用来源时，状态与数值按最弱来源标注。

## 三、速度估算

**Decode（生成速度）与 Prefill（提示词处理）必须分开**，不能用一个数代替。

Decode 至少考虑：每 Token 权重读取、历史 KV 读取、新 KV 写入、其他运行时流量。上下文越长 KV 读取通常越大；批量生成时权重读取可由多序列摊销。MoE 按激活专家估访问流量，但**容量仍按全部常驻权重算**。

带宽上限：

```
T_BW = BW_effective / Bytes_per_token
```

同时考虑计算上限、量化反量化、注意力实现、CPU/GPU 分层、PCIe 传输。**不得把 CPU 与 GPU 带宽简单相加**，也不得无依据假设传输与计算完全重叠。

速度必须给区间，并标注「估算/实测」、对应模型/量化/上下文/并发/引擎/卸载方案、主要瓶颈、置信度。区分总吞吐与单序列速度。

**区间上下界必须各自写出依据**：实测吞吐 / 实测方差 / 调度抖动之一。不得使用无来源经验系数；区间宽度不得窄于实测方差。没有可靠依据时写「暂无法可靠估算」，**禁止编造 Token/s**。

## 四、PolyStrata + KVMem 第二路径

作为第二条推理路线检查，但**不能视为「增加显存」或「压缩/消除权重」**，也不能覆盖普通引擎的原判定。用户 AI Vault 已集成该引擎；仍须核验本机 AI Vault、Worker 版本、模型兼容性、实际能力响应（如 `/props`）与启动日志。

参考版本 `v0.1.45-poly.9`，但**冲突时以实机为准**：`VERSION` / `BUILD-INFO` / `launcher-capabilities.json` 优先级高于参考文档。版本与能力差异必须在页面上标出，不得照抄参考文档当本机结论。

该参考版本下 CUDA 单卡明确支持 Qwen 3.5 MoE（`qwen35moe` GGUF，F16/Q8_0 KV）与 Gemma 4 26B-A4B（GGUF，F16/int8/int8k KV）。具体模型、权重量化、组合仍需逐项核验；**不得把模型家族支持扩大成所有 GGUF 支持**。Gemma 新能力需配套重建 Worker。HIP 仍为实验路径。单 GPU、不支持多 GPU 与 batch MTP；batch 用普通解码，MTP 仅独占执行；启用 KVMem 不允许 `truncate_middle`。不兼容写「该引擎未确认支持」。

**单独核算资源，不套普通引擎整模型驻留公式**：

- **权重/专家**：区分 GPU 专家驻留、RAM 专家池、文件映射、专家交换。记录 `--ram-experts-mib`：`-1` 映射默认、显式 MiB 为 RAM 专家池、`-2` 自动预算；不得假定自动策略最快
- **KV**：分别记录 `context`、`budget`、`reserve`、`host-mib`、KV 类型、并发、可选 SSD。逻辑上下文可大于 GPU 驻留 KV；KVMem 通过有界 Query/replay 与 RAM/SSD 分层管理，**不代表所有历史同时留在显存**
- **系统内存/磁盘**：`host-mib` 是 KV/状态配额，不是 Worker 进程总内存上限；另计 RAM 专家、模型映射、Python 前端、工作区、传输缓冲、Gemma 状态图像、OS 余量

保留普通引擎矩阵为基线；对兼容模型另建 PolyStrata 专属判定。普通引擎「放不下」不代表 PolyStrata 也放不下，反之亦然。

速度只引用相同模型、硬件、配置的实测；比较必须固定模型文件/量化、输入输出长度、上下文、并发、KV 类型、budget/reserve、Host 配额、专家策略、CPU 线程、MTP、Worker 版本、测试轮次，并分别记录 Prefill、Decode、首 Token 延迟、显存/RAM 峰值、磁盘 I/O。**不同配置的数据不得拼成一个速度结论**。

只有当兼容性与资源预算有证据支持、且确实改变模型可行性时，才展示「另一条路」；同时说明系统内存、I/O、部署复杂度与性能波动代价。**先评估软件路线，再建议购买硬件**。

## 五、报告信息架构

阅读顺序必须是「先得到判断，再比较选择，再查看证据，最后验证」，**不能先铺硬件参数**。

1. **结论首屏**：设备名、评估日期、最关键瓶颈数值、一句话说明它限制了什么、最值得尝试的档位（首选 + 备选 + 取舍理由）、数据完整度/置信度。**首屏不是封面**，无需滚动就能回答：最受什么限制、能跑到哪一档、下一步做什么。数据不足时明写「暂不能可靠判定」，不能用视觉掩盖缺口。
2. **模型能力矩阵**：模型规模 × 量化 × 上下文，三维独立筛选控件；点选单元格只作补充定位，不能替代筛选。显示四态、占用/预算、速度区间（有依据时）、限制资源。
3. **关键证据**：按对结论的影响排序，每个数字说明它改变了哪个选择。不影响判定的测量进脚注/附录。
4. **计算依据**：容量构成、KV、卸载临界点、上下文上限、失败机制，可折叠。
5. **性能与升级**：Decode/Prefill 分开、速度区间、瓶颈、最小有效升级、升级前后对比，**必须同时列出未被改变的格**。没有可靠报价来源不编造价格。不能改变判定就写「不建议购买」。
6. **验证方法**：固定模型文件、量化、引擎版本、上下文、并发、卸载参数，实测 Token/s、显存峰值、RAM 峰值，用于验证或推翻预测。

**必须有数据缺口与未实测项清单**，并注明每一项对结论的影响。

## 七、交付前自检

- 数据没有伪造；普通引擎与 PolyStrata 路径没有混算
- 模型架构与 Worker 兼容性已核验，实机与参考文档冲突已按实机裁决并标注
- 显存、RAM 专家池、Host KV 配额、SSD 分别核算；共享内存没有错误累加
- KV 符合模型架构与并发；MoE 容量与访问流量分开
- 四态矩阵有预算与瓶颈；Decode/Prefill 分开；速度有区间与依据
- 「放不下」说明资源与失败阶段；升级确实改变判定并列出未改变的格
- 夜灯主题与交互真实生效；HTML 单文件离线可开、适配窄屏和打印

# 判分实现

全部在 `scripts/scorers.py`，纯标准库。**没有 LLM 裁判**——这是设计决定，不是还没做。

## 为什么不用 LLM 裁判

| 问题 | 后果 |
| --- | --- |
| 不可复现 | 同一答案两次判分可能不同，分数失去可比性 |
| 偏好冗长 | 长回答被系统性打高分，与「答对」无关 |
| 偏好自身风格 | 用哪个模型当裁判，就偏向哪种文风 |
| 破坏离线 | 本地评测一旦依赖 API 裁判，结论无法离线复现也无法分享 |
| 责任模糊 | 分不清「模型差」还是「裁判差」 |

替代方案：只测**可程序化验证**的东西。不可验证的（语气、风格、说服力）明确不做，写进各维的「不代表什么」。

## verdict 语义

| verdict | 含义 | 计分 |
| --- | --- | --- |
| `correct` | 答案命中标准答案 | 1.0 |
| `incorrect` | 答了但错 | 0.0 |
| `abstain_correct` | 不可答问题，正确弃答 | 1.0 |
| `over_abstain` | 可答问题却弃答 | 0.0 |
| `hallucinated` | 不可答问题却给出具体答案 | 0.0 |
| `premise_ok` | 指出错误前提并给正确事实 | 1.0 |
| `premise_missed` | 沿用错误前提 | 0.0 |
| `no_call_ok` | 无匹配工具，正确未调用 | 1.0 |
| `spurious_call` | 无匹配工具却调用 | 0.0 |
| `unknown_tool` | 调用了清单里没有的工具 | 0.0 |
| `arg_mismatch` | 工具对但参数错 | 0.0 |
| `count_mismatch` | 调用数量不符 | 0.0 |
| `request_failed` | HTTP 层失败，不是模型问题 | 0.0 且计入 errors |

`request_failed` 必须与模型答错区分开。报告里单列 `errors`，有 error 就标「不完整」。

## 数值抽取优先级（math）

```
#### 123        → 123
\boxed{123}    → 123
"所以答案是 123" → 123   （结论词之后的数值）
"1/6 + 1/12"   → 取末位数值（无结论词时）
```

结论词表：`所以 / 因此 / 故 / 答案 / 应为 / 等于 / 合计 / 总计 / 总共 / 共 / 需要 / 得到 / 结果 / 应是 / 即`。

**坑**：`1/6 + 1/12 = 1/4` 这种算式，若不先遮罩分数，`1/6` 会被拆成 `1` 和 `6`，末位变成 6。`_positional_numbers` 先匹配分数并记录覆盖区间，再匹配普通数值时跳过已覆盖位置。

## 弃答判定顺序（factual）

**先判命中，再判弃答**。

```python
if _alias_hit(response, aliases):   # 命中就是对的
    return 1.0, "答案命中", ...
if abstained:                        # 没命中且像弃答
    return 0.0, "过度弃答", ...
return 0.0, "答错", ...
```

反例：`"巴黎是法国首都，这不存在争议"` 含「不存在」，若先判弃答会误判成 over_abstain。命中优先避免了这类误伤。

弃答词表见 `scorers.ABSTAIN_RE`，加词时必须同时加一条 selftest 用例，否则无法证明没引入误伤。

## 工具调用解析

三种形态，按顺序尝试：

1. **JSON**（含 `<tool_call>` 包裹、OpenAI `{name, arguments}`、数组）：从任意文本中捞平衡 JSON 片段
2. **Python 调用**：`name(arg=val)`，参数支持嵌套括号、引号
3. 都没有 → 无调用

**参数比对**：
- 键集严格相等（默认）；`strict:false` 时只要求 gold 键存在
- 值归一化：`bool` → 布尔；数字与数字字符串 → float 四舍五入 6 位；字符串 → 小写去空格
- 多调用配对用消元，与顺序无关

## 区间算法

| 场景 | 方法 | 理由 |
| --- | --- | --- |
| 均值 | bootstrap 百分位法，2000 次，种子 20260101 | 不假设正态；n 小也能给 |
| 比例 | Wilson 区间 | n 小时比正态近似可靠，不会越界 |

n < 5 时 bootstrap 退化为点估计（返回 lo=hi=mean），报告里应理解为「样本不足以给区间」。

## ECE（期望校准误差）

5 桶，每桶算 |平均置信度 − 实际正确率|，按样本占比加权。

- 置信度样本 < 5 → 返回 `None`，报告显示「—」
- 置信度解析：`置信度: 85` 或 `confidence: 0.85` 都支持，>1 自动除以 100
- ECE 只作趋势参考。n=16 时任何校准结论都不稳

## 改判分的纪律

1. **先加 selftest 用例，再改代码**。没有失败用例的改动无法证明修好了什么
2. 改完跑 `python scripts/selftest.py`，必须全绿
3. 已有结果用 `python scripts/eval.py score --out <dir>` 重判，**不要**手改 `scores.jsonl`
4. 重判后对比：分数变化是否只影响你意图影响的题？若波及无关题，说明改动过宽
5. 契约变了同步改 `measurement-contract.md`

## 明确不做

- ❌ 开放式生成质量的自动评分（无可靠程序化方法）
- ❌ 多轮对话中的状态保持（需要真实执行环境，见 `benchmark-basis.md` 的 BFCL multi-turn）
- ❌ 代码正确性的沙盒执行验证（需 Docker/沙盒，超出本地评测范围）
- ❌ 跨引擎分数对比（llama.cpp 与 vLLM 的模板与采样实现不同，分数不可直接比）

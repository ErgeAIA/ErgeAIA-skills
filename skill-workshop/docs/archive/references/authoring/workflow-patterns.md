## 1. 顺序工作流 {#1-顺序工作流}


### 分解操作为顺序步骤


对于复杂任务，将操作分解为清晰、顺序的步骤。在目标 Skill 的 SKILL.md 开头为 Claude 提供流程概述通常很有帮助。

#### 顺序工作流示例


```markdown
填写PDF表单涉及以下步骤：

1. 分析表单 (运行 analyze_form.py)
2. 创建字段映射 (编辑 fields.json)
3. 验证映射 (运行 validate_fields.py)
4. 填写表单 (运行 fill_form.py)
5. 验证输出 (运行 verify_output.py)
```

#### 顺序工作流设计原则


| 原则 | 说明 |
|------|------|
| 清晰性 | 每个步骤应该明确、无歧义 |
| 可执行性 | 每个步骤应该有明确的操作或输出 |
| 可验证性 | 关键步骤后应该有验证机制 |
| 原子性 | 每个步骤应该完成一个单一任务 |

## 2. 条件工作流 {#2-条件工作流}


### 引导通过决策点


对于具有分支逻辑的任务，引导 Claude 通过决策点。

#### 条件工作流示例


```markdown
1. 确定修改类型：
   **创建新内容？** → 遵循下面的"创建工作流"
   **编辑现有内容？** → 遵循下面的"编辑工作流"

2. 创建工作流: [步骤]
3. 编辑工作流: [步骤]
```

#### 条件工作流设计原则


| 原则 | 说明 |
|------|------|
| 明确条件 | 决策条件应该清晰、可判断 |
| 完备覆盖 | 所有可能的情况都应该有对应分支 |
| 默认路径 | 提供默认或回退路径 |
| 避免嵌套 | 尽量避免深层嵌套的条件 |

## 附录

### A. 工作流类型对比


| 工作流类型 | 适用场景 | 复杂度 |
|-----------|---------|--------|
| 顺序工作流 | 线性任务、标准操作流程 | 低 |
| 条件工作流 | 分支决策、多路径处理 | 中 |
| 混合工作流 | 复杂业务逻辑、多场景处理 | 高 |

### B. 最佳实践


1. **从概述开始**: 在详细步骤之前提供高层次概述
2. **使用编号列表**: 清晰显示步骤顺序
3. **标注关键决策点**: 在条件分支处明确标注
4. **提供示例**: 为复杂工作流提供具体示例

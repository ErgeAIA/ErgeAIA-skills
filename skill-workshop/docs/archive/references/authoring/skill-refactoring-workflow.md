## 重构已有 Skill


---

## 1. 什么情况下应该走重构流程

### 先判断这是不是“重构问题”


优先进入重构流程的典型信号：

- 主 `SKILL.md` 持续变长，已经难以充当路由层
- 同一段正文同时承担“说明概念 + 路由 + 示例 + 规则”
- references 变多了，但主文档没有明确“何时读取哪份参考”
- workflow 边界混乱，新增需求只能靠继续堆步骤解决
- 修改后经常担心打破已有触发边界或加载路径


## 2. 重构前先盘点什么

### 盘点现有 Skill 的稳定边界


重构前至少盘点：

- 当前 `description` 和触发示例在界定什么边界
- 哪些规则属于强制常驻加载
- 哪些内容只是解释层，理论上可以下沉
- 哪些 references 已经承担稳定职责，不能随意打散
- 当前验证入口有哪些：`validate`、`package`、`scripts/validate_skill.py`

- 先记录“哪些内容必须留在主 SKILL.md”
- 再记录“哪些内容可以移动，但不能改变触发或校验语义”

## 3. 重构强度判断

### 先判断该改到什么深度


若本次重构是由结构评估报告触发，优先复用评估报告中的“推荐重构方案”结论，再决定实施范围。

| 强度 | 适用情形 | 典型动作 | 暂不建议做什么 |
| --- | --- | --- | --- |
| 轻量修订 | 目标清楚、主结构基本成立，问题主要集中在措辞模糊、局部重复、少量缺边界 | 修措辞、补链接、补缺失输入规则、删重复、补少量输出结构 | 不要顺手重排整个目录或改 workflow 主骨架 |
| 结构重整 | 主文档过厚、workflow 边界混乱、references 失衡、验证入口不清，但核心目标仍稳定 | 瘦主文档、重排 workflow、补决策矩阵入口、下沉长解释、统一 references 角色 | 不要在同一轮里顺手重定义 Skill 能力边界 |
| 深度重构 | 目标边界失真、多套能力混杂、目录架构和执行链都不稳定，继续局部修补收益很低 | 重新定义能力边界、拆分或合并子流程、重建目录与规则层次、重新规划验证闭环 | 不要在没有明确取舍说明的情况下直接大改并覆盖旧行为 |

- 若主要问题可以通过 1-3 处局部补丁解决，优先判为 `轻量修订`
- 若核心目标不变，但需要明显调整主文档职责、workflow 边界或 references 分层，优先判为 `结构重整`
- 若问题已经上升到“这个 Skill 到底在做什么、应不应该拆开”的层面，才进入 `深度重构`
- 若已有评估报告的加权总分，可先用默认映射辅助判断：`80-100 -> 轻量修订`，`60-79 -> 结构重整`，`<60 -> 深度重构`
- 若存在致命单点问题、材料不完整或明确的用户硬约束，可覆盖总分默认映射，但要把覆盖理由写清楚
- 无论哪一档，都先说明保留什么、不改什么，再进入实际修改

## 4. 推荐重构顺序

### 按稳定顺序迁移，而不是到处同时改


推荐顺序（内容三层分层）：

1. 先明确主 `SKILL.md` 要保留哪些**AI 专属**路由与强制入口；人类可读内容归 `README.md`，按需细节归 `references/`
2. 把解释层、示例层、模板层下沉到 `references/`；**人类可读内容（定位、用法、设计哲学）另建 `README.md`，禁止塞回 SKILL.md`**
3. 若涉及复杂边界变化，先补 workflow 映射表，再改正文
4. 再修 references 之间的阅读顺序、互链和目录示意
5. 最后跑校验与访问性核实，并按需要修正版本、锚点和打包产物

@警告: 不建议一上来同时重写主文档、references 结构和脚本校验，否则很难判断是哪一层破坏了行为。

## 5. 渐进加载检查清单

### 检查是否伤到加载路径


重构后重点检查：

- 主 `SKILL.md` 是否仍明确指向强制参考文档
- 新增参考文档是否有清晰入口（且 frontmatter 带 `trigger-when` 明确加载条件），而不是只是“存在于目录里”
- 是否出现“孤儿规则文件”：有内容但主流程再也不会路由到它
- 是否把本该常驻的强制规则下沉得过深
- 是否把本该按需读取的解释层重新塞回主文档


## 6. 回归校验清单

### 用校验而不是直觉收尾


重构后至少检查（均为**强制**，非可选清单）：

- `python scripts/skill_cli.py validate <skill-dir>` —— 现已自动覆盖：所有引用路径（含代码块内、正文裸路径）存在性 + 新增 references 的 `trigger-when`
- 抽取 SKILL.md 全部 `references/*.md` / `scripts/*.py` / `examples/*.md` 路径验证存在（validate 自动做，确认返回 PASS）
- 若有 `scripts/validate_skill.py`，继续跑工程硬校验
- `python scripts/skill_cli.py package <skill-dir>`
- 版本三处是否一致
- 若从 SKILL.md 抽出了人类内容，确认 `README.md` 已创建且被 SKILL.md 引用

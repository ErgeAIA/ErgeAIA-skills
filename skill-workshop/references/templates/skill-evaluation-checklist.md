# Skill 结构评估内部清单

<!-- @类型: 参考模板 -->
<!-- @目的: 为已有 Skill 或相关可复用指令资产的结构评估提供一份可量化、可复核、可回填到 8 维评分表的内部 checklist -->
<!-- @场景: 已完成初步阅读与证据收集，准备做 8 维打分，或在正式交付前复核是否漏掉关键问题 -->
<!-- @触发条件: 当需要把“定性判断”进一步压成可复核的 8 维评分时使用 -->

> **一句话**: 这是给评估者自己用的量化清单，帮助把 8 个维度打得更稳，而不是第二套对外报告模板
> **版本**: v1.0.1
> **用途**: 辅助 8 维打分、复核高风险问题、减少漏判
> **适用范围**: 已有 Skill 或相关可复用指令资产的结构质量评估、评分前复核、交付前自检

## 1. 使用方式

### @步骤1: 把清单当成“评分前复核器”

<!-- @类型: 操作步骤 -->
<!-- @优先级: 必须 -->
<!-- @验证点: 已明确这份文档服务内部打分与复核，不替代正式评估报告 -->
<!-- @验证方式: 最终交付物仍使用 `skill-evaluation.md`，本清单仅用于形成更稳定的 8 维分数 -->
<!-- @ID: step-use-checklist-as-pre-score-review -->

- @动作: 先读目标 Skill / 指令资产与关键 companion files，再使用本清单逐维复核
- @动作: 每项用 `✅ / ⚠️ / ❌ / N/A` 标记状态
- @动作: 每个维度的状态可直接换算为该维度的 `0-100` 分
- @动作: 正式评估报告仍优先使用 [skill-evaluation-template.md](skill-evaluation-template.md)

## 2. 量化规则

### @步骤2: 用统一换算把勾选项变成维度分

<!-- @类型: 操作步骤 -->
<!-- @优先级: 必须 -->
<!-- @验证点: 已明确 checklist 如何量化成 8 维分数 -->
<!-- @验证方式: 能根据同一维度内的勾选结果算出 `维度分 / 100` -->
<!-- @ID: step-convert-checks-to-dimension-score -->

默认换算规则：

- `✅ = 1`
- `⚠️ = 0.5`
- `❌ = 0`
- `N/A = 不计入分母`

维度分计算方式：

```text
维度分 = (该维度实际得分 / 该维度可计分项总分) * 100
```

整体总分仍按既有权重计算：

| 维度 | 权重 |
| --- | ---: |
| 目标与适用边界 | 15% |
| 指令一致性与精准性 | 15% |
| 输入输出契约 | 15% |
| 工作流完整性 | 15% |
| 鲁棒性与安全边界 | 15% |
| 可维护性与渐进披露 | 10% |
| 可验证性与测试闭环 | 10% |
| Token 效率与冗余控制 | 5% |

@提示: 如果某维度命中单点致命问题，例如核心 workflow 缺失、主文档完全失去路由职责、关键验证入口不存在，即使勾选分不低，也应允许人工下调该维度分，并在报告里解释原因。

## 3. 八维量化清单

### @步骤3: 逐维复核，再回填到评分表

<!-- @类型: 操作步骤 -->
<!-- @优先级: 必须 -->
<!-- @验证点: 8 个维度都能通过 checklist 获得更稳定的评分依据 -->
<!-- @验证方式: 每个维度至少有 4 个可检查项，并能生成维度分与主要扣分原因 -->
<!-- @ID: step-review-eight-dimensions-with-checklist -->

```markdown
# Skill 结构评估内部清单

## 1. 目标与适用边界
- [ ] `✅ / ⚠️ / ❌ / N/A` 目标是否能用一句话说清
- [ ] `✅ / ⚠️ / ❌ / N/A` 适用场景是否明确
- [ ] `✅ / ⚠️ / ❌ / N/A` 不适用场景或边界是否明确
- [ ] `✅ / ⚠️ / ❌ / N/A` 触发语或命中信号是否稳定
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否容易误分流到其他 workflow

## 2. 指令一致性与精准性
- [ ] `✅ / ⚠️ / ❌ / N/A` 主要指令是否都服务同一个核心目标
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否存在模糊词、装饰性要求或不可执行表述
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否存在冲突规则或隐含优先级不明
- [ ] `✅ / ⚠️ / ❌ / N/A` 决策规则是否足够明确
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否避免了无关能力混入

## 3. 输入输出契约
- [ ] `✅ / ⚠️ / ❌ / N/A` 输入要求是否明确
- [ ] `✅ / ⚠️ / ❌ / N/A` 缺失输入时的处理是否明确
- [ ] `✅ / ⚠️ / ❌ / N/A` 输出结构是否明确
- [ ] `✅ / ⚠️ / ❌ / N/A` 输出语言、粒度或格式是否可预期
- [ ] `✅ / ⚠️ / ❌ / N/A` 不确定性表达是否有规则

## 4. 工作流完整性
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否存在稳定的最小步骤链
- [ ] `✅ / ⚠️ / ❌ / N/A` 默认动作和关键分流点是否清楚
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否缺少关键步骤导致无法闭环
- [ ] `✅ / ⚠️ / ❌ / N/A` 步骤顺序是否合理
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否避免了明显多余步骤

## 5. 鲁棒性与安全边界
- [ ] `✅ / ⚠️ / ❌ / N/A` 对缺失材料或不完整文件是否有处理规则
- [ ] `✅ / ⚠️ / ❌ / N/A` 对冲突要求或模糊目标是否有处理规则
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否明确限制编造、越权或误执行
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否保留用户原意与关键约束
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否说明局限性与假设

## 6. 可维护性与渐进披露
- [ ] `✅ / ⚠️ / ❌ / N/A` 主文档（如 `SKILL.md` / 主指令文件）是否仍是路由层或稳定入口
- [ ] `✅ / ⚠️ / ❌ / N/A` 长解释、模板、示例是否已合理下沉
- [ ] `✅ / ⚠️ / ❌ / N/A` references 之间职责是否清晰
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否存在明显重复维护
- [ ] `✅ / ⚠️ / ❌ / N/A` 新增文档是否都有明确入口

## 7. 可验证性与测试闭环
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否存在 `validate` 或等价硬校验入口
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否能区分结构校验与人工判断问题
- [ ] `✅ / ⚠️ / ❌ / N/A` 修改后是否有最小回归验证路径
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否有评测闭环、回放或复盘入口

## 8. Token 效率与冗余控制
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否存在明显重复段落或重复规则
- [ ] `✅ / ⚠️ / ❌ / N/A` 是否存在低价值背景说明或装饰性表达
- [ ] `✅ / ⚠️ / ❌ / N/A` 长说明是否可压缩而不伤边界
- [ ] `✅ / ⚠️ / ❌ / N/A` 关键约束是否集中，而不是散落重复

## 9. 高风险问题速查
- [ ] `✅ / ⚠️ / ❌ / N/A` 主文档不再像路由层
- [ ] `✅ / ⚠️ / ❌ / N/A` 缺少关键 workflow 或关键步骤
- [ ] `✅ / ⚠️ / ❌ / N/A` 缺少验证入口
- [ ] `✅ / ⚠️ / ❌ / N/A` 规则冲突导致执行不稳定
- [ ] `✅ / ⚠️ / ❌ / N/A` references 有明显孤儿文档

## 10. 常见修复方向速查
- 目标与边界不清：收窄目标，补适用 / 不适用场景
- 指令模糊或冲突：改成可执行规则，补优先级
- 输入输出不稳：补默认输入假设与输出结构
- workflow 断裂：补最小步骤链与默认动作
- 主文档过厚：把解释层、模板层和示例层下沉到 `references/`
- 缺验证入口：补 `validate`、最小回归建议或评测闭环入口
```

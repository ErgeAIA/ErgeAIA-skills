# 场景输入模板

<!-- @场景: 目标 Skill 存在高频复用场景，且这些场景逐步形成稳定、高效的提问模板 -->

> **一句话**: 这是按“使用场景”沉淀的输入模板，不是工作流说明书
> **版本**: v1.8.0
> **用途**: 作为 `references/examples/*.md` 的编写基线
> **适用范围**: 需要沉淀高频场景输入模板的目标 Skill

## 使用原则

- 先从“用户常见使用场景”出发组织模板，而不是从工作流步骤出发
- 模板关注三件事：当前场景与目标、为达成目标提供哪些信息、最后希望拿到什么结果
- 目标 Skill 可以根据“目的”自动或半自动匹配到对应工作流，但模板本身不负责工作流路由
- 每个高频场景默认维护 1 个主模板；只有存在稳定分支时，才扩展到 2-3 个模板
- 模板文档本身也要维护版本：frontmatter `version`、头部 `> **版本**`、文末 `## 版本历史` 三处保持一致

## 固定结构

1. `适用场景`
2. `建议提供的信息`
3. `可直接复制输入模板`
4. `裁剪规则（可选）`

> **边界**: 本文档不负责工作流路由；工作流应由目标 Skill 根据“目的”和“提供的信息”判断

## 适用场景

- 场景名称: `<场景名称>`
- 一句话需求: `<用一句话概括这次请求，例如：创建一个处理 PDF 的 Skill>`

## 裁剪规则（可选）

- 某些场景不需要所有字段时，可以直接删掉不重要的字段
- 如果差异主要来自目标不同，优先保留同一场景模板，把差异写进 `适用场景` 里的目标描述
- 只有当场景本身稳定分化为不同输入习惯时，才拆成多个模板

## 落地建议

- 固定模板来源保留在 `references/templates/`，例如 `references/templates/scenario-input-template.md`
- 自动生成的场景示例文档写到 `references/examples/input-template-<english-slug>.md`
- 目标 Skill 需要新增模板时，优先复制上面的“可直接复制输入内容”再做最小改写
- 模板标题与内容都优先体现“场景名”，不要直接把模板写成工作流名
- 可用命令：`python scripts/skill_cli.py generate-templates <skill-path>`，基于 `SKILL.md` 的工作流自动生成场景示例草稿，并更新 `references/examples/index.md`
- 若覆盖已有模板，建议递增补丁版本，并把最新变更写入 `## 版本历史` 首条；版本历史最多保留 5 条

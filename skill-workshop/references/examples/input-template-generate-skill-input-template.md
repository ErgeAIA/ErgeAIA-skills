> **用途**: 用于“为某个 Skill 生成输入模板”这个高频使用场景，帮助一次性给出高质量输入
> **版本**: v0.1.0
> **边界**: 本文档不负责工作流路由；工作流由目标 Skill 根据“目的”和“提供的信息”判断
> **来源**: 基于 `理解并创建Skill` 工作流手工收敛，适合作为长期复用的示例

## 适用场景

- 场景名称: `为某个 Skill 生成输入模板`
- 对应工作流: `理解并创建Skill`
- 一句话需求: `为专利价值评估 Skill 生成一个可直接复制的场景输入模板`
- 我这次想做什么: `先为目标 Skill 沉淀一份可复用的输入模板，而不是直接展开完整实现`
- 我最关注什么: `模板结构清晰、字段不重复、用户复制后稍作补充就能直接使用`
- 我希望最终得到什么结果: `一份可直接复制的输入模板，以及必要的裁剪建议、文件命名建议和落位建议`

## 建议提供的信息

- 背景信息: 这个 Skill 是做什么的，当前为什么先要模板而不是直接写 Skill
- 现有材料: 目标 Skill 的 `SKILL.md`、已整理好的工作流、历史示例、相关参考文档
- 关键约束: 模板是否必须聚焦某个场景，是否要求文件名英文、是否要做版本管理
- 判断标准: 什么样的模板算好，例如可复制、低歧义、不承担路由职责、后续好维护
- 参考样例（可选）: 你认可的模板写法、历史优秀示例、希望模仿的表达风格
- 其他补充（可选）: 是否需要同步生成 `references/examples/index.md`、是否需要自动生成多份草稿

## 来源工作流摘要

- 先明确这个 Skill 的真实触发场景、典型请求和核心痛点
- 先区分哪些内容应该写进 `SKILL.md`，哪些更适合下沉到 `references/`
- 模板文档只负责输入补全，不反向承担工作流路由职责

## 裁剪规则（可选）

- 如果目标 Skill 只有一个非常明确的场景，可进一步压缩字段，只保留最必要的信息
- 如果差异主要来自目标不同，优先保留同一场景模板，把变化收敛到“目标”和“期望结果”
- 如果已经有成熟模板，可只让助手补充命名、结构和裁剪建议，而不是整份重写

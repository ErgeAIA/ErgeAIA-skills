> **用途**: 用于 `用户需要评测已有 Skill` 这个高频使用场景，帮助一次性给出高质量输入
> **版本**: v0.2.0
> **边界**: 本文档不负责工作流路由；工作流由目标 Skill 根据“目的”和“提供的信息”判断
> **来源**: 基于 `评测已有 Skill` 工作流整理，并适合后续继续人工收敛

## 适用场景

- 场景名称: `用户需要评测已有 Skill`
- 对应工作流: `评测已有 Skill`
- 一句话需求: `帮我审一下这个 Skill，并保存成文档`
- 我这次想做什么: `先判断这个已有 Skill 的结构质量、主要问题和重构优先级`
- 我最关注什么: `先拿到带证据的评估结论，不急着直接改 Skill`
- 我希望最终得到什么结果: `一份结构化评估报告，包含 8 维评分表、加权总分，以及明确的后续重构建议`

## 建议提供的信息

- 目标 Skill 路径: `指出要评测的 Skill 在哪里`
- 当前关注点: `例如结构是否清晰、references 是否失衡、验证机制是否完整、主文档是否过厚`
- 评分口径偏好（可选）: `默认使用 8 个维度，每项 /100，并按权重计算总分`
- 现有材料: `当前 SKILL.md、关键 references、脚本、validate 输出或历史讨论`
- 是否需要保存成文档: `例如是否写入 skill-evaluation.md，是否有指定路径`
- 命名或措辞约束: `是否需要隐藏本技能名称、是否使用团队口径、是否有固定标题`
- 其他补充（可选）: `任何可能影响评测重点或结论表达的信息`

## 可直接复制输入模板

我现在要处理的场景是：`用户需要评测已有 Skill`。
这次希望你直接帮我完成：`先判断这个已有 Skill 的结构质量、主要问题和重构优先级`。
我最关注的是：`先拿到带证据的评估结论，不急着直接改 Skill`。
我希望最终拿到的结果是：`一份结构化评估报告，包含 8 维评分表、加权总分，以及明确的后续重构建议`。

为避免你来回追问，我先把关键信息一次性给你：

- 目标 Skill 路径：`{补充要评测的 Skill 路径}`
- 当前关注点：`{补充结构质量、references 分层、验证机制、正文长度等关注项}`
- 评分口径偏好（可选）：`{默认按 8 个维度分别打 0-100 分，并按权重汇总总分}`
- 现有材料：`{补充当前 SKILL.md、references、脚本、validate 输出或历史讨论}`
- 是否需要保存成文档：`{补充是否写入 skill-evaluation.md，是否有指定路径}`
- 命名或措辞约束：`{补充是否要隐藏本技能名称、是否使用团队口径或固定标题}`
- 其他补充（可选）：`{补充其他可能影响评测重点或表达方式的信息}`

如果信息已经足够，请直接进入最合适的评测流程；先收集证据、运行 `validate`、再输出评估结论。除非我明确要求，否则不要直接修改目标 Skill。

## 来源工作流摘要

- 盘点目标 Skill 的主文档、companion files 与验证入口
- 运行 `validate`，记录结构硬伤与项目规则问题
- 归纳主要优点、主要问题与重构优先级
- 输出 8 维评分表：每维 `0-100`，并按权重计算总分 `/100`
- 生成 `skill-evaluation.md` 或用户指定路径的评估文档

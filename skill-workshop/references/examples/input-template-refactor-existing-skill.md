> **用途**: 用于 `用户需要重构已有 Skill` 这个高频使用场景，帮助一次性给出高质量输入
> **版本**: v0.1.0

## 适用场景

- 场景名称: `用户需要重构已有 Skill`
- 对应工作流: `重构现有 Skill`
- 一句话需求: `帮我重构这个 Skill 的 workflow 边界和 references`
- 我这次想做什么: `整理已有 Skill 的主文档、workflow 边界、references 分层和验证机制`
- 我最关注什么: `不破坏现有触发边界和渐进加载路径，同时让结构更清晰`
- 我希望最终得到什么结果: `一版完成重构、通过校验、边界更清晰的 Skill`

## 建议提供的信息

- 当前 Skill 路径: `指出要重构的 Skill 在哪里`
- 当前痛点: `例如主文档太长、references 混乱、workflow 边界不清、版本规则不统一`
- 现有材料: `当前 SKILL.md、相关 references、脚本、校验输出或历史讨论`
- 关键约束: `哪些入口不能改、哪些文件不能动、哪些规则必须保留`
- 判断标准: `你会如何判断这轮重构是否成功`
- 其他补充（可选）: `任何可能影响重构路径的信息`

我现在要处理的场景是：`用户需要重构已有 Skill`。
这次希望你直接帮我完成：`整理已有 Skill 的主文档、workflow 边界、references 分层和验证机制`。
我最关注的是：`不破坏现有触发边界和渐进加载路径，同时让结构更清晰`。
我希望最终拿到的结果是：`一版完成重构、通过校验、边界更清晰的 Skill`。

为避免你来回追问，我先把关键信息一次性给你：

- 当前 Skill 路径：`{补充要重构的 Skill 路径}`
- 当前痛点：`{补充主文档太长、workflow 混乱、references 失衡、验证缺失等问题}`
- 现有材料：`{补充当前 SKILL.md、references、脚本、校验日志或历史讨论}`
- 关键约束：`{补充哪些入口不能改、哪些规则必须保留、哪些文件不能动}`
- 判断标准：`{补充你会如何判断这轮重构是否成功}`
- 其他补充（可选）：`{补充其他可能影响判断的信息}`

如果信息已经足够，请直接进入最合适的重构流程；不要先解释有哪些工作流，除非你确实无法判断。

## 来源工作流摘要

- 盘点当前 Skill 的触发边界、强制规则和外部依赖
- 判断问题属于内容膨胀、workflow 混乱、references 失衡，还是验证缺失
- 先决定哪些内容保留在主 `SKILL.md`，哪些下沉到 `references/`
- 若涉及复杂边界调整，先补 workflow 映射，再改正文
- 修改后统一跑 `validate` / `package`

# C1.1 需求收集与复杂度判断

<!-- @类型: 工作流 -->
<!-- @优先级: 必须 -->

## @工作流: 需求收集

### @步骤1: 统一确认

<!-- @类型: 操作步骤 -->
<!-- @验证点: 已确认是否进入创建流程，且关键待确认问题已集中澄清 -->

- @动作: 确认任务类型：创建新 Skill
- @动作: 确认交付物：SKILL.md + 目录结构 + 可选脚本/模板
- @动作: 确认是否需要 workflow 设计（中等以上复杂度必须）
- @动作: 若用户明确不需要进入当前流程，记录结论后转入轻量执行路径

### @步骤2: 收集触发示例

<!-- @类型: 操作步骤 -->
<!-- @验证点: 至少收集到 2 条真实触发语句 -->

- @动作: 至少整理 2 条真实触发语句（"用户说什么会触发 Skill"）
- @动作: 整理 1 份痛点总结
- @动作: 输出一句话定义（作用 + 触发场景 + 边界）
- @动作: 建议先判定目标模式归属（Tool Wrapper / Generator / Reviewer / Inversion / Pipeline，见 [skill-patterns.md](../authoring/skill-patterns.md)），它决定 SKILL.md 的结构骨架（灌知识 / 固定输出 / 清单审查 / 先问后做 / 强制多步）

### @步骤3: 判断复杂度

<!-- @类型: 决策步骤 -->
<!-- @验证点: 已完成复杂度分级 -->

- @动作: 读取 `references/rubrics/complexity-rubric.md`
- @动作: 对照六维触发条件逐项判定
- @动作: 标注"轻量 / 中等 / 复杂"，并写明依据
- @动作: 轻量 Skill 记录为什么可跳过完整 workflow 映射
- @动作: 复杂 Skill 记录后续必须补 workflow 映射表

## 输出

- 一句话定义
- 触发示例 ≥2 条
- 复杂度判断 + 依据
- 下一步：进入 C1.2 规划与初始化

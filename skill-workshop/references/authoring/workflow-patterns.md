## 1. 顺序工作流 {#1-顺序工作流}

<!-- @范围: 线性任务处理 -->

### @步骤1: 分解操作为顺序步骤

<!-- @类型: 操作步骤 -->
<!-- @优先级: 必须 -->
<!-- @说明: 对于复杂任务，将操作分解为清晰、顺序的步骤 -->
<!-- @验证点: 步骤列表具备顺序、原子性与可验证性 -->
<!-- @验证方式: 检查每步是否包含明确动作/产物/验证，且无跨步耦合 -->
<!-- @ID: step-design-sequential-workflow -->

对于复杂任务，将操作分解为清晰、顺序的步骤。在目标 Skill 的 SKILL.md 开头为 Claude 提供流程概述通常很有帮助。

#### 顺序工作流示例

<!-- @类型: 示例 -->
<!-- @用途: 展示顺序工作流的结构 -->
<!-- @ID: ex-sequential-workflow -->

```markdown
填写PDF表单涉及以下步骤：

1. 分析表单 (运行 analyze_form.py)
2. 创建字段映射 (编辑 fields.json)
3. 验证映射 (运行 validate_fields.py)
4. 填写表单 (运行 fill_form.py)
5. 验证输出 (运行 verify_output.py)
```

#### 顺序工作流设计原则

<!-- @类型: 设计原则 -->
<!-- @用途: 指导顺序工作流的设计 -->

| 原则 | 说明 |
|------|------|
| 清晰性 | 每个步骤应该明确、无歧义 |
| 可执行性 | 每个步骤应该有明确的操作或输出 |
| 可验证性 | 关键步骤后应该有验证机制 |
| 原子性 | 每个步骤应该完成一个单一任务 |

## 2. 条件工作流 {#2-条件工作流}

<!-- @范围: 分支决策处理 -->

### @步骤2: 引导通过决策点

<!-- @类型: 操作步骤 -->
<!-- @优先级: 必须 -->
<!-- @说明: 对于具有分支逻辑的任务，引导Claude通过决策点 -->
<!-- @验证点: 分支条件清晰且覆盖主要情形 -->
<!-- @验证方式: 检查是否有默认路径、是否避免深层嵌套且条件可判断 -->
<!-- @ID: step-design-conditional-workflow -->

对于具有分支逻辑的任务，引导 Claude 通过决策点。

#### 条件工作流示例

<!-- @类型: 示例 -->
<!-- @用途: 展示条件工作流的结构 -->
<!-- @ID: ex-conditional-workflow -->

```markdown
1. 确定修改类型：
   **创建新内容？** → 遵循下面的"创建工作流"
   **编辑现有内容？** → 遵循下面的"编辑工作流"

2. 创建工作流: [步骤]
3. 编辑工作流: [步骤]
```

#### 条件工作流设计原则

<!-- @类型: 设计原则 -->
<!-- @用途: 指导条件工作流的设计 -->

| 原则 | 说明 |
|------|------|
| 明确条件 | 决策条件应该清晰、可判断 |
| 完备覆盖 | 所有可能的情况都应该有对应分支 |
| 默认路径 | 提供默认或回退路径 |
| 避免嵌套 | 尽量避免深层嵌套的条件 |

## 附录

### A. 工作流类型对比

<!-- @类型: 决策表 -->
<!-- @用途: 帮助选择合适的工作流类型 -->

| 工作流类型 | 适用场景 | 复杂度 |
|-----------|---------|--------|
| 顺序工作流 | 线性任务、标准操作流程 | 低 |
| 条件工作流 | 分支决策、多路径处理 | 中 |
| 混合工作流 | 复杂业务逻辑、多场景处理 | 高 |

### B. 最佳实践

<!-- @类型: 最佳实践 -->
<!-- @用途: 工作流设计的一般性建议 -->

1. **从概述开始**: 在详细步骤之前提供高层次概述
2. **使用编号列表**: 清晰显示步骤顺序
3. **标注关键决策点**: 在条件分支处明确标注
4. **提供示例**: 为复杂工作流提供具体示例

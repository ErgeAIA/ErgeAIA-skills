# distill · 沉淀可复用经验

## 目标

把本次会话里**值得下次复用**的东西固化下来：踩过的坑、验证有效的做法、确立的禁区。

产物是给未来的 agent 看的预防规则，不是本次操作的回放记录。

## 前置检查

| 检查项 | 不通过时 |
|---|---|
| `docs/.ai/lessons.md` 是否存在 | 不存在 → 回复缺失项，引导先跑 `vibe-init` |
| 本次会话是否有可提炼的内容 | 没有 → 明说，不生成空条目 |

## 可提炼的四类

| 类别 | 判定标准 |
|---|---|
| 踩坑 | 本次实际发生的问题、回归或异常，且已定位到根因 |
| 有效做法 | 本次验证有效、下次可复用的做法 |
| 禁区 | 本次确立的"不要这样做"，附原因 |
| 关键权衡 | 影响方向的选择，含被放弃的选项与理由 |

不具备以上特征的内容（过程流水、被推翻的中间方案、无根因的抱怨）不写。

## 条目格式（追加到 `docs/.ai/lessons.md` 末尾）

```markdown
## YYYY-MM-DD · <一句话标题>

- **症状**：<观察到的现象或报错>
- **根因**：<底层原因>
- **预防规则**：<下次如何提前避免>
- **适用场景**：<什么情况下这条规则生效>
```

**禁区类条目**用「预防规则」写"禁止做什么 + 原因"，不写替代方案。

## 写入规则

- **仅追加**，禁止重写整个文件、禁止改写既有条目。
- 一条一事件，不合并多个无关问题。
- 追加前扫描既有条目去重：同一根因已存在则跳过，或补充新的表现。
- **不写入解决方案的完整代码**。需要代码时写路径指针，避免档案膨胀与版本漂移。
- **不修改 `AGENTS.md`**：若某条经验上升为项目级规则，提示用户走 `vibe-init` 的增量维护，不自行写入契约。
- 所有条目**必须有本次对话依据**。无依据的内容一律不写，宁可少写。

## 终止回复

只回复：追加条数、跳过（去重）条数、`lessons.md` 路径。无内容时回复「本次无可提炼的稳定经验」。

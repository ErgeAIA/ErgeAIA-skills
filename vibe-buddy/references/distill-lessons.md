# distill · 沉淀调试经验

## 目标

把**反复调试才定位到根因**的问题固化成可复用的预防规则，让下一个 agent 不再重踩。

产物是给未来的 agent 看的诊断档案，不是本次调试过程的回放。

## 前置检查

| 检查项 | 不通过时 |
|---|---|
| `docs/.ai/debug-log.md` 是否存在 | 不存在 → 回复缺失项，引导先跑 `vibe-init` |
| 是否有已定位根因的问题 | 只有现象、根因未知 → 明说，等根因确认后再沉淀 |

## 什么值得记

| 值得记 | 不值得记 |
|---|---|
| 反复调试、间歇复现、报错难察的问题 | 一次就改好、无诊断价值的笔误 |
| 已定位到根因并可给出预防规则 | 只有现象，根因仍在猜 |
| 影响面大或容易复发的坑 | 个人环境偶发、无法复现的问题 |

## 条目格式（追加到 `docs/.ai/debug-log.md` 末尾）

````markdown
### BUG-001 · YYYY-MM-DD · <一句话标题>

- **症状**：
- **根因**：
- **修复**：
- **预防规则**：
````

编号递增，先读文件取最大编号再加一。

## 写入规则

- **只追加**，禁止重写整个文件、禁止改写既有条目。
- 一条一个问题，不合并多个无关问题。
- 追加前扫描既有条目去重：同一根因已存在则跳过，或补充新的表现。
- **不贴大段修复代码**，需要时写文件路径与行号，避免档案臃肿与版本漂移。
- 所有条目**必须有本次对话依据**；根因未确证时写「根因待确认」，不编造。
- 与 `decision-log.md` 的分界：**修复手法**归本文件，**技术选型与偏离 PRD 的决策**归 `vibe-sync`。
- 若某条经验应上升为项目级规则，提示用户走 `vibe-init` 的增量维护，不自行写入 `AGENTS.md`。

## 终止回复

只回复：追加的条目编号、去重跳过条数、`debug-log.md` 路径。无内容时回复「本次无可沉淀的调试经验」。

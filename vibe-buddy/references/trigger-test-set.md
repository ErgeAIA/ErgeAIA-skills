# vibe-buddy 触发测试集

> 评估方式：干跑推演（把每条输入交给 Agent，观察是否激活本技能）。真实触发率需在带技能索引的运行时中复测。

## 正面集（应触发，≥10 条）

```
初始化项目                                    # 英文式触发词中文
vibe-init                                     # 英文触发词
帮我给这个项目生成 AGENTS.md                    # 自然语言
这个仓库还没接入 AI 协作记忆，初始化一下          # 自然语言 + 前置条件
vibe-init，根目录已经放好 PRD.md 了             # 带前置条件
同步进度                                       # 中文触发词
vibe-sync，把刚做完的登录模块沉淀一下            # 详细场景
把这次的稳定增量更新到项目进度里                  # 自然语言
把这次踩的坑记下来                              # 调试记录，归 vibe-sync
这个 bug 排查到根因了，记录一下                   # 详细场景
更新日志 / 把这次改动写进 CHANGELOG              # 更新日志，归 vibe-sync（文件已存在才追加）
vibe-sync，同步进度并补一条更新日志              # 组合意图，仍路由 vibe-sync，日志按契约可选追加
上下文快满了，写个交接文档给下一个 agent          # 详细场景
vibe-handoff                                  # 英文触发词
交接上下文，我要换到新会话继续做                  # 自然语言
帮我交接一下                                    # 口语短触发，默认按生成交接文档处理
经验蒸馏                                       # 中文触发词
把这一轮 UI 整改里反复的做法提炼成可复用经验        # 详细场景
vibe-distill，把这几轮的做法沉淀成经验库           # 详细场景
审查项目                                       # 中文触发词
审查技术栈                                     # 中文触发词
vibe-audit                                    # 英文触发词
帮我审查一下这个后端项目的架构                    # 自然语言 + 开发类项目
这个项目只有 CLAUDE.md，帮我迁移到 AGENTS.md     # 契约迁移，归 vibe-init

把 Claude 的项目规则迁移到 AGENTS.md             # 自然语言迁移

我用 AI 开发这个项目，帮我初始化协作契约            # v1.6.0 新定位措辞
把进度和决策固化下来，让下个会话接得上              # v1.6.0 新定位措辞（Core Task 原话）
```

**覆盖**：五个触发词（init / sync / handoff / distill / audit）全覆盖，含英文触发词、中文触发词、自然语言变体、带前置条件、口语短触发，初始化状态机 C / D 的迁移场景，以及 v1.6.0「AI 编程全过程协作管理」定位下的自然措辞。

**语气覆盖**：正式（vibe-init）、口语（把这次踩的坑记下来）、详细（带具体模块名）、短触发（同步进度）。

**失败前置覆盖**：项目无 `AGENTS.md` 时触发 `vibe-sync`，应被前置检查拦下并引导 `vibe-init`。

**与 changelog-manager 的分界**：单独一句「更新日志 / 写进 CHANGELOG」有两个归属——把**本轮已完成改动**的用户可见摘要追加进项目**已有**的 `CHANGELOG.md` → `vibe-sync`（v1.6.0 的 description 不再携带「更新日志」措辞，此类输入可能被 changelog-manager 先接走，属可接受结果）；建立、规范化或归档 CHANGELOG 体系 → changelog-manager。带 `vibe-sync` 明示的组合意图（下条）必须路由本技能。

## 技能内路由校验（同一技能，必须落到正确契约）

| 输入 | 应路由到 |
|---|---|
| 把这次踩的坑记下来 / 这个 bug 定位到根因了 | `vibe-sync` —— 记流水事实，落 `debug-log.md` |
| 更新日志 / 写进 CHANGELOG | `vibe-sync` —— 仅当项目根 `CHANGELOG.md` 已存在时追加用户可见变更；无文件不代建 |
| 把这几轮反复的做法提炼成可复用经验 | `vibe-distill` —— 提炼规则，落 `experience/` |
| 审查项目 / 审查技术栈 / vibe-audit | `vibe-audit` —— 只读审查开发类项目，落 `docs/.ai/audit/`；Skill 项目转 skill-workshop |

三者不可互串：`vibe-sync` 只记录不提炼，`vibe-distill` 只提炼不复述流水，`vibe-audit` 只审查不代写过程文档。

## 负面集（不应触发但易混淆，≥5 条）

```
帮我把这个迭代的任务拆成待办清单              # 任务计划，交给计划类技能
帮我把这段模糊需求写成 PRD                    # 需求转译，不是项目管理
给这个项目写一份 README                       # 面向人类的文档写作
新建一个 React 组件                           # 代码生成
跑一下 pnpm test                              # 终端命令，本技能禁止运行
提交这些改动                                  # Git 操作，交给 git 类技能
提议一个规格变更                              # 规范生命周期管理，不在范围内
我刚才在旧会话交接了一份代码                    # 事实陈述，不是命令
接管项目，先告诉我现在做到哪了                  # 接管义务，由 AGENTS.md 承担
继续上次的活，先摸清现状                       # 同上，不依赖触发词
把 AGENTS.md 翻译成英文                       # 翻译任务
审计这个 skill / 帮我评审 skill 质量            # Skill 项目评审，交给 skill-workshop
帮我把这个 skill 重构一下                      # Skill 重构，交给 skill-workshop
保留一个 Claude 专属 CLAUDE.md                  # 边界：用户明确意图，不强制删除
记住我的偏好，以后所有项目都这么做                 # Agent 自身跨项目记忆，不是项目协作档案
```

**易混淆说明**：

| 输入 | 为什么不触发 |
|---|---|
| 拆待办清单 | 任务计划与排期不在本技能范围 |
| 写成 PRD | 需求转译属于需求侧技能 |
| 写 README | 面向人类的项目文档，与本技能的 `docs/.ai/` 过程档案区不同 |
| 跑 pnpm test | 白名单外命令，本技能不跑 |
| 提交这些改动 | Git 操作由专门的技能负责 |
| 提议规格变更 | 规范生命周期管理已明确移出范围 |
| 我刚才在旧会话交接了一份代码 | 陈述过去事实，不是指令 |
| 接管项目 / 继续上次的活 | 接管是目标项目 `AGENTS.md` 的 `Permissions` 义务，每会话自动生效，**不设触发词**。若这里触发了本技能，说明「接管不由本技能触发」这条强规则没被读到 |
| 翻译 AGENTS.md | 翻译任务，与项目协作管理无关 |
| 审计 skill / 评审 skill / 重构 skill | Agent Skill 质量工作归 skill-workshop；`vibe-audit` 只针对开发类项目，命中 `SKILL.md`+`name` 即转交不自审 |
| 保留一个 Claude 专属 `CLAUDE.md` | 用户明确要求保留 Claude 专属规则时不属于默认 `vibe-init`：按用户明确意图处置（保留或单独迁移），不得强制删除；**默认 `vibe-init` 仍执行 `AGENTS.md` 单源策略**，不创建、不保留 `CLAUDE.md` |
| 记住我的偏好，以后所有项目都这么做 | 那是 Agent 自身的跨项目记忆（运行时记忆目录），本技能只写**单个项目**内的协作档案；v1.6.0 起 description 与「非目标」都显式排除，命中即回归失败 |

## 回归方法

1. 逐条把正面集作为输入，观察是否激活 vibe-buddy，且路由到正确的参考文件。
2. 逐条把负面集作为输入，观察是否**未**激活。
3. 记录类输入必须路由到 `vibe-sync`，提炼类输入必须路由到 `vibe-distill`，审查类输入必须路由到 `vibe-audit`——互串即回归失败。
4. 接管类措辞（「接管项目」「继续上次的活」）应**不触发**本技能——它们由 `AGENTS.md` 义务覆盖，触发即回归失败。
5. Skill 审计类措辞（「审计这个 skill」「评审 skill 质量」）应**不触发**本技能，或触发后必须转交 skill-workshop 而非自审。
6. 陈述句（「我刚才……」）应被识别为非命令。
7. 每次修改 `description` 或触发词后必须完整回归。
8. 迁移类输入（「迁移到 AGENTS.md」「整理成唯一规则文件」）应路由 `vibe-init` 并按初始化状态机执行；任何路径都不得新建 `CLAUDE.md`，触发后新建即回归失败。
9. Agent 自身记忆类措辞（「记住我的偏好，以后所有项目都这么做」）应**不触发**本技能——它只写单个项目内的协作档案，触发即回归失败。

## 阈值

| 指标 | 阈值 | 未达标时 |
|---|---|---|
| 正面集命中率 | ≥ 90% | 低于 90% 增强 description 意图词；低于 70% 视为 description 失效 |
| 负面集误触发率 | ≤ 10% | 高于 10% 增强边界声明；高于 30% 视为触发范围失控 |
| 接管类措辞不触发率 | ≥ 90% | 在 SKILL.md 强规则中强化「接管不由本技能触发」条款 |
| 技能内路由正确率 | 100% | 在 SKILL.md 路由表与各契约的「分界」小节强化记录 / 提炼 / 审查的分工表述 |
| Skill 审计不自审率 | 100% | 命中 Skill 信号时必须转交 skill-workshop；自审即回归失败 |

### 2026-09-10 · 按最新最佳实践把触发词清单改为意图句

**依据（联网核实）**：

- **agentskills.io「Optimizing skill descriptions」**：四原则之一是「**聚焦用户意图，而非实现细节**」；技能适用面宽时「**不要**把每一种可能的应用都列进描述」——`overly long descriptions bloat the agent's context across many skills`；且**禁止**把失败查询里的关键词逐条塞进描述（原文称之为 overfitting）。长度软建议「几句话到一个短段落」，硬上限 1024 字符。
- **Anthropic 官方最佳实践**：`description` 的硬约束只有「非空、≤1024 字符、不能含 XML 标签」，**未给任何建议字数区间**；写法是「**功能句 + `Use when…` 触发句**」两段都要有；官方正例中的关键词**嵌在 `Use when…` 句内**（`or when the user mentions PDFs, forms, or document extraction`），不是裸词表；并要求**始终第三人称**。**该页全篇未提「Pushy」**——此说法出自 agentskills.io。

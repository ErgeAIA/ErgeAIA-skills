# audit · 只读审查开发类项目

## 目标

对**开发类项目**（前端 / 后端 / Web）做一次只读审查，产出可复核的审计报告：每条结论绑定证据，只给问题 + 证据 + 方向。

**不改被审项目。** 唯一写入是审计报告；源码、配置、依赖与既有过程文档一律只读。

**不评审 Skill 项目。** 目标命中 Skill 判定信号时停止自审，转交 skill-workshop。

## 前置检查

| 检查项 | 不通过时 |
|---|---|
| 目标类型是否为 Skill 项目 | 命中 → 停止自审，只输出转交说明（见下节），不写报告 |
| 目标类型是否为开发类项目（前端 / 后端 / Web） | 否或无法判定 → 停下问用户，不猜、不自审 |
| `docs/.ai/` 是否存在 | 不存在 → 回复缺失项，引导先跑 `vibe-init`，不代建 |
| `docs/.ai/audit/` 是否存在 | 不存在 → **首次 `vibe-audit` 时创建该目录**（含 `.gitkeep`），并在终止回复中说明 |
| 本次是否读到可审查的代码或配置 | 全无 → 明说「无可审查对象」，不生成空报告 |

## 目标类型前置判定

只认可观测信号，按序判定：

| 信号 | 判为「有」的条件 |
|---|---|
| Skill 项目 | 目标根（或技能目录）存在 `SKILL.md`，且 frontmatter 含 `name` 字段 |
| 开发类项目 | 存在源码目录、依赖清单或锁定文件（如 `package.json` / `pyproject.toml` / `Cargo.toml` / `go.mod` 等），或有应用/服务入口代码 |

- **Skill 项目** → 停止自审。只输出转交说明：目标路径、已观测的 frontmatter 字段、是否含 `scripts/`、判定依据一句话，并指向 skill-workshop。不写入 `docs/.ai/audit/`。
- **开发类项目** → 继续执行本契约。
- **两者皆不像或信号矛盾** → 停下问用户，不猜、不自审。
- **用户坚持在本技能内审 Skill 项目** → 拒绝，说明本契约标尺（代码质量 / 架构 / 技术栈）不适用。

## 审查范围（开发类）

| 维度 | 看什么 | 不做什么 |
|---|---|---|
| 代码质量 | 可读性、重复、错误处理空洞、明显坏味道、危险写法（能静态看出的） | 不跑测试/构建；不重构 |
| 架构 | 目录边界、模块耦合、分层是否被穿层、配置与代码职责是否清晰 | 不重画架构、不迁移目录 |
| 技术栈 | 锁定文件与实际用法是否一致、版本是否自相矛盾、依赖是否明显冗余或缺失 | **不动栈**；不建议换框架/重写 |
| 优化方向 | 在**不换栈**前提下可走的改进方向 | 不产出待办、排期、整改清单 |

## 事实源与取材

写任何一条结论前先取客观事实，**不得只凭会话记忆或印象落笔**：

| 序 | 事实源 | 取什么 |
| -- | ------ | ------ |
| 1 | 项目源码与配置文件（只读） | 实际结构、写法、耦合点；数字与位置必须实测 |
| 2 | 依赖清单与锁定文件 | 技术栈构成与精确版本 |
| 3 | `AGENTS.md` 与 `docs/.ai/`（存在时） | 项目约定、已知坑、已有决策，避免把「已裁决事项」再报成新问题 |
| 4 | `git status --short`、`git log --oneline -n <N>`、`git diff --stat` | 工作区与提交现状；**仅本项目在 Git 仓库内时可用** |
| 5 | 本次会话上下文 | 仅作补充；与 1–4 冲突时以客观源为准 |

- 条目里的数字（处数、文件数、出现次数）必须**实测**，禁止按印象写
- `git diff --stat` **不显示未跟踪文件**，为空不等于没有改动，以 `git status --short` 为准
- 项目不是 Git 仓库 → 跳过第 4 项，视为无此事实源，不报错
- **写入范围只有审计报告**；取材可及项目内任意文件与白名单只读命令

## 证据绑定（硬规则）

- **每条结论必须带 `路径:行`**，格式与 distill 的 How 一致；读不到原文或行号对不上 → 该条写「证据不足」，**不写入断言**。
- 无法从文件、锁定文件、git 或白名单命令确证的内容 → 写「未知」或「证据不足」，禁止编造。
- 发现的问题若已写在 `debug-log.md` / `decision-log.md` → 用 `BUG-NNN` / `DEC-NNN` 指针引用，不复述。
- 全篇无法取证 → 中止，只输出已取证部分（若有）；无任何取证 → 明说并停止，不写空报告。

## 报告结构

````markdown
---
title: <一句话审计主题>
type: audit
project: <工程标识>
updated: YYYY-MM-DD
description: >
  <本次审查覆盖了哪些维度与目录范围>
---

# 审计报告 · YYYY-MM-DD

## 1. 范围
目标路径、判定为开发类项目的依据、实际覆盖的目录/文件范围、未覆盖部分。

## 2. 技术栈快照
来自锁定文件与配置的实测构成（工具与版本）；不一致处单独标出。

## 3. 问题清单
每条：严重度 / 维度（质量|架构|技术栈）/ 结论 / 证据（`路径:行`）/ 方向（不动栈）。
证据不足的条目单独放在「证据不足」小节，不混入问题清单。

## 4. 证据不足与未覆盖
读不到、未扫到、用户未开放的范围。

## 5. 方向摘要
按优先级排列的改进方向（仍是方向，不是待办与排期）。
````

- 工程标识取法：用户指定 → 依赖清单 name → 项目根目录名
- `updated` 写当日；事后修订本文件时同步改

## 命名与落盘

- 路径：`docs/.ai/audit/audit-YYYY-MM-DD.md`
- 当日已有同名文件时追加语义后缀：`audit-YYYY-MM-DD-<slug>.md`
- 后缀仍撞名时加两位序号：`audit-YYYY-MM-DD-<slug>-02.md`，**不回头打扰用户**
- **永不覆盖**。目标路径已存在就换名
- `docs/.ai/audit/` 不存在时创建目录并写入 `.gitkeep`（若目录为空且尚未有报告）

## 硬性约束

- **只写审计报告这一个落点**；对报告本身仍遵守「不覆盖 / 不静默」。
- **不改被审项目任何文件**：源码、配置、`.gitignore`、依赖清单一律只读。
- **不代写过程文档**：`project-progress.md` / `decision-log.md` / `debug-log.md` / `experience/` / `agents-changelog.md` / `init-report.md` 一律不碰；若有应记事项，在终止回复中建议用户跑 `vibe-sync` 或 `vibe-distill`。
- **只给问题 + 证据 + 方向**；不生成待办、排期、整改清单、检查表。
- **脱敏**：密钥、token、凭据、连接串、个人隐私一律不写入报告；发现即替换为占位符。
- **只跑白名单内的只读 Git 命令**（`rev-parse` / `status` / `log` / `diff --stat`）；构建、测试、依赖安装与任何写命令都不跑。
- **Skill 项目不自审**，只转交。

## 不写什么

- 不写代码、不重构、不改依赖。
- 不写 `docs/.ai/` 的进度、决策、调试三份与 `experience/`。
- 不写 `AGENTS.md` 契约区或事实区。
- 不把「建议」写成「已发生」；意图文档里的计划选型不写入技术栈快照，快照只认锁定文件与实跑/实读配置。

## 终止回复

三行：

1. 报告落盘路径（或「未写入：Skill 项目已转交 / 无可审查对象 / 证据不足中止」）
2. 结论统计：问题 N 条 · 证据不足 M 条 · 未覆盖范围一句话
3. 是否发现应记入 `docs/.ai/` 的事项（有则建议跑 `vibe-sync`；无则写「无」）

若判为 Skill 项目，终止回复改为转交说明，不写报告路径。

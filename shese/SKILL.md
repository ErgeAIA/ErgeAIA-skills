# 设色 · Shese

> 设色者，布色于位，明其阶次。先定其所用，再正其所失。

## 定位

在用户声明的场景下让一套配色读得舒服、不丢原意；让不懂色彩学的人也能拿到结论，并看见它在真实界面里的样子。

Core Task：

```text
声明阅读目标 → 还原语义角色 → 展开 alpha 合成 → 按机制判定 → 最小改动优化 → 出预览页与 token
```

三条轨道（审查 / 生成 / 取源）共用一条判定链，见「执行步骤」分轨。

**唯一标准**：指定场景下阅读舒适性最高且不丢失原意；审美偏好不得凌驾于可读性，结论先行，不做赞美式点评。

## 不可违背

1. **目标先行**：先声明阅读目标（用途、单次时长、环境亮度、字号与字重、信息密度），再反推尺度。禁止拿通用数字套场景。
2. **判据是机制，不是数字**：每条判定写明依据机制；数字只是该机制在常见场景的刻度，不是门禁。
3. **三级标注**：硬底线（违反即不通过，只覆盖直接破坏阅读或造成误读）／参考锚点（默认起点，可浮动但须给理由）／目标推导（由目标算出，目标不同结论必不同）。
4. **建议优先于判定**：多数问题是区间问题——给区间 + 推荐点 + 代价，把选择权交回用户；不以「通过 / 不通过」收尾。
5. **偏离要补偿**：说明服务哪个目标、用什么补偿（提字号、加字重、拉层级明度差、减小高彩度面积）。
6. **alpha 与合成**：带 alpha 的文字 token 必须声明允许出现的最差背景面，对比结论以该面合成实色为唯一依据，未声明即无效；按浏览器口径在 sRGB 合成，多重叠加沿整条链算，不能只算一层；设计工具在线性空间混色时两端不同，以浏览器渲染为准并注明。
7. **对比是双向约束**：上限与下限同等重要。深色正文避免纯白、浅色正文避免纯黑；极高对比带光晕与眩光，长阅读反而疲劳。
8. **文字结论必须绑定字号与字重**：小字号、细体属高空间频率，需更高对比补偿；大字号或粗体可略低。不给脱离字号的无条件合格判定。
9. **不擅自替换品牌色与主色相**，也不为「更高级」引入新色相：新增色值必须对应已存在的语义缺口；品牌色造成可读性问题时只指出并给替代用途。
10. **每条结论挂在具体色值与机制上**：不接受纯审美评价；深浅分别审查，不用一套结论覆盖。
11. **语言与符号**：交付文本跟随输入语言，不用 emoji 与装饰符号；本文件的 🔴 只是流程标记，不外传。
12. **冲突有裁决顺序**：下限合规 > 舒适上限 > 层级 > 语义一致 > 生理负荷 > 审美；提升下限若会触发上限禁令，改换角色档或承载面，不硬提。
13. **一 token 兼两职时两职都要过**：同一色同时作文字、图标、边界或填充时，分别验，任一不过即不算通过。

## 输入

标准输入包（缺失项按最合理假设执行，标【假设】）：

1. 家族 / 主题标识
2. 色值集合：十六进制列表或语义 token 名
3. 用途与明暗模式
4. 不可改动项
5. 透明度信息：哪些 token 使用 alpha、透明度值、预期落点与最差背景面

生成轨另加：风格意图或症状词、禁忌（一票否决）、可选参考锚点。

用户报主题编号或主题名时，按 `references/theme-source.md` 取 `palette.md` 全表作输入；编号每次现读 `INDEX.json` 复核。

仅当缺失会直接导致结论错误才提 ≤3 问。颜色一律按合成后实色计算；透明度缺失按不透明处理并标【假设】。

## 角色与判定面（判定前先定）

1. **先定角色再定对比**：承载阅读（正文、长句、表格）／辅助（标签、说明、时间戳）／弱化（占位、禁用、装饰）／反色（色块上的前景）。弱化不得复用到需阅读处；反色按实际填充色单独验。
2. **判定面取最差**：文字会落在 bg / surface / elevated / card / hover / selection / accent 上，逐一测，取最差面作结论。
3. **彩度与补偿**：中性低彩度最适合承载正文；高彩度只用于短词、标题与点睛，小字号须查彩色边缘；对比不足先补对比而非换字体，品牌色必须低对比时用字号字重或色块补偿。

## 判定表（十二项，逐项读出「等级 + 默认起点 + 依据机制」）

| 审查项 | 等级 | 默认起点与依据机制 |
| --- | --- | --- |
| 承载阅读的正文对比 | 硬底线 | 起步档按 APCA 官方字号—字重矩阵查表（格点见 `references/thresholds.md` 1.1），不脱离字号字重；相对亮度比只记账。依据：对比度、空间频率、极性 |
| 次级 / 弱化文字 | 锚点 | 可低于正文，但只用于短标签与辅助信息，不承载长句。依据：对比度、阅读负荷 |
| 文字 token 含 alpha | 硬底线 | 声明合成基准面，且最差面仍满足其角色要求。依据：透明度与合成 |
| 层级明度差 | 锚点 | 相邻层级在 OKLCH 拉开可辨差距，深色通常需更大；多级阶梯达不到 0.10 时用边框补并注明。依据：感知均匀空间、侧抑制 |
| 高彩度色的面积 | 锚点 | 点睛与品牌色保持小面积，占比随密度调整；关键是与正文争不争注意力。依据：面积与彩度 |
| 大面积填充彩度 | 锚点 | 背景与卡片保持中等以下彩度。依据：面积与彩度 |
| 深浅模式基础色 | 硬底线 | 不用纯黑底与纯白正文；取值由阅读环境与时长决定。依据：暗适应、浦肯野效应、光晕 |
| 语义色可区分性 | 硬底线 | 状态色之间需同时有明度或形态差异，不只靠色相。依据：色觉差异、冗余编码 |
| 色觉模拟校验 | 硬底线 | 三类模拟（protan / deutan / tritan）下正文仍可读、语义色仍可区分；任一失效即调整。门禁组见 `references/thresholds.md` 3.2。依据：色觉差异 |
| 品牌色相适配 | 锚点 | 不替换品牌色相，可调明度与彩度以适配层级与对比。依据：色彩恒常性、品牌调性 |
| 控件边界与分界 | 锚点 | 可寻址控件（按钮、输入框、可聚焦容器）边界 ≥3:1；纯分界（卡片、表格线）按 ΔE-OK 1.1–1.5 判可辨。依据：同时对比、侧抑制 |
| 要点与品牌强调 | 锚点 | 同正文档，只许小面积短文本、禁承载长段；品牌铺开面积经验上限约 10%，超出改中性衬底。依据：空间频率、面积与彩度、光晕 |

逐条点名机制（15 条见 `references/mechanisms.md`）；点不出机制名的不算判定。

## 执行步骤

每步按「输入 → 产出 → 命令」走，命令在技能目录下原样可跑。**先判轨道再走链**：

- **审查轨**（给了色值）→ 步骤 1。
- **生成轨**（只给意图 / 症状词 / 参考锚点）→ 按 `references/generate.md` 出意图卡与 2–3 套骨架不同的候选，每套跑满 1–8 并单独给结论，最后出对照（骨架差异 / 强弱 / 推荐 / 代价）；不许只验一套就用它。
- **取源轨**（报主题编号 / 主题名）→ 按 `references/theme-source.md` 取 palette 全表，再按审查轨走。

| 步 | 输入 | 产出与命令 |
| --- | --- | --- |
| 1 阅读目标声明 | 用途、单次时长、环境亮度、字号与字重、信息密度；缺项标【假设】 | 3–5 句目标句，六字段齐备，后续尺度只能从这里推。先取 `references/scenes.md` 最近画像的默认档，再按实际改并写明理由 |
| 2 角色还原 | hex 列表或语义 token 名（别名自动归一） | 十个语义角色（底层背景 / 抬升面 / 浮层 / 边框 / 正文 / 次级文字 / 弱化文字 / 点睛 / 品牌色 / 语义色）各绑一个 hex；`oklch "#c9d1d9" "#8b949e" --json` 读 L / C / h，按 L 排层级、按 h 分家族，映射不了的 单列并说明原因 |
| 3 意图解读 | 步骤 2 的 L / C / h 分布，尤其 C 最高的两三个色 | 一句话调性 + 哪几个 hex 承担该表达；判据是彩度与色相位置，不是形容词堆叠 |
| 4 合成层清理 | 哪些 token 带 alpha、透明度、可能落点 | `composite "#ffffffb3" --on "#22222B"`，多层按自顶向下作位置参数、`--on` 只给最底层；产出「透明度 → 沿链合成实色 → 最差面」。带 alpha 的文字 token 没给最差面则结论无效 |
| 5 文字—背景矩阵 | 每个文字 token 的 (hex, role, size, weight) 与全部承载面 | 每 token 的 WCAG 比值（记账）+ APCA Lc（判定）+ 要求值 + 最差面 + 缺口；exit 1 = 最差面不达标。层级差跑 `delta`、色觉跑 `cvd` |
| 6 逐项判定 | 合成实色、矩阵与 ΔE | 先按角色与判定面定角色、定最差面，再走判定表十二项，每行读出「等级 + 实测 + 机制 + 建议」；能算的给实测数，其余给区间 + 推荐点 + 代价并注明人工判断 |
| 7 优化 | 步骤 6 不达标的项 | 用 `oklch` 取原 L / C / h、只动一个分量、`--to-hex` 出新值；产出改后色值表（角色｜原值｜新值｜理由｜目标）。改完重跑 4、5、6 确认无回归 |
| 8 交付 | 定稿色值 + 判定结论 | 快档四件（结论 / 预览页 / 决策摘要 / token JSON）；完整报告走深档，见 `references/audit-report.md` |

命令样例：单点复核 `contrast "#8b949e" "#0d1117" --size 13 --weight 400`；矩阵写 spec 喂脚本，各 token 用自己的角色与字号（全局旗标一视同仁，别用）：

```json
{"text": {"text": {"hex": "#c9d1d9", "role": "body", "size": 16, "weight": 400},
          "textMuted": {"hex": "#8b949e", "role": "aux", "size": 13, "weight": 400}},
 "surface": {"bg": "#0d1117", "card": "#1c2128"}}
```

`matrix --tokens spec.json`；`delta "#1c2128" "#161b22" "#0d1117"` 按传入顺序两两相邻，低于 0.10 即塌陷、exit 1；`cvd` 只管色觉塌陷。`preview --tokens bg=#0d1117 --tokens text=#e6edf3 --out preview.html`（`--tokens` 可重复；`--mode light` 只改标签，浅色预览须喂浅色值）。

> 🔴 **CHECKPOINT 1 · 目标未定不动手**：用途、时长、字号字重缺两项先问（≤3 问）；不回就取最近默认档并标【假设】——目标错，后面全白算。
> 🔴 **CHECKPOINT 2 · 判定链未清完不改色**：合成实色与矩阵都在手上，每个不达标项能说出「差多少、卡在哪条机制」；最差面未定先回步骤 4。
> 🔴 **CHECKPOINT 3 · 硬底线未过不交付**：正文对比、alpha 最差面、纯黑底/纯白正文、语义色可区分、色觉模拟任一复测不过，停止交付并摆出「改了什么 / 还差多少 / 需用户定什么」。
> 🔴 **CHECKPOINT 4 · 交付前自检**：结论含「最差面 + 缺口 + 依据机制」；预览页、决策摘要、token JSON 三处同一 token 必须同值。

## 工具（精确数字必须来自这里）

下表命令均以 `python scripts/shese.py <子命令>` 调用（零依赖，Python ≥3.10；`--help` 查参数）。

| 子命令 | 用途 |
| --- | --- |
| `oklch` | hex ↔ OKLCH，`--to-hex` 反向；超色域收缩并标注 |
| `contrast <text> <bg>` | 单配对的 APCA Lc 与相对亮度比；给 `--size` + `--weight` 按官方矩阵定档，不给则按 `--role body\|aux\|hint`（60 / 45 / 30） |
| `composite` | 带 alpha 的颜色沿链在 sRGB 合成 |
| `matrix` | 文字 × 承载面矩阵，标最差面；`--tokens` 的 text 条目写 `{"hex","role","size","weight"}` 让每 token 用自己的档，写字符串则沿用全局参数 |
| `delta <colors...>` | 相邻层级 ΔE-OK（默认 0.10） |
| `cvd <colors...>` | 三类色觉模拟 + ΔE-OK（默认 0.10） |
| `mix <A> <PCT> <B> [--space oklab\|srgb]` | A 占 PCT% 与 B 混色；一端可写 `transparent`（= 该色带 alpha）；派生色阶用 oklab，srgb 仅复算 |
| `preview --tokens name=HEX --out <file> [--mode dark\|light]` | 注入 `assets/scene-preview.html` 出填色副本；外壳用品牌主题色，只审注入 token；bg 与 `--mode` 极性不符时 stderr 提醒，退出码不变 |
| `selftest` | 官方测试向量自检（改脚本必跑） |

退出码：0 = 成功（判定类即全部达标）／1 = 判定不达标／2 = 输入或环境错误。token 别名归一到 14 个标准名。

hex 参数一律加引号（PowerShell 下裸 `#` 会被当注释截断、静默失败）；起步档由脚本按官方矩阵查表，禁止插值或凭记忆给数；脚本给单点判据，交付仍要连区间与代价。

## 卡住时怎么办（触发条件 / 一线修复 / 仍失败兜底）

读到症状先查表，别硬推。第三列是前两步都没解决时的动作，不是可选项。

| 触发条件 | 一线修复 | 仍失败兜底 |
| --- | --- | --- |
| 色值非十六进制或位数非 3/4/6/8（exit 2） | 把 rgb()/hsl()/命名色按浏览器口径换成十六进制重跑 | 仍解析不了就记【不可计算】单列，该行写「无法判定 + 缺什么」，不猜不跳 |
| token 名不在 14 个标准名内（exit 2） | 按别名归一（`background`→`bg`、`ok`→`success`、`muted`→`textMuted`），重跑 | 仍无法归一按 L / C 映射最近角色，结论写明人工映射 |
| 承载面是 hover / selection / 半透明层（含模板混色底；脚本只认 14 个标准名） | 先 `composite` 合成实色，再挑最近标准面名承载（`matrix --text … --surface …`），列名标真实面名（hover @ card） | 合成链超两层或依赖未定交互态，单列标【未定面】，不算通过 |
| 色值缺角色（只有 bg 与 text） | 只对已给角色下结论，缺的写【缺】 | 不补齐、不虚构 token；token JSON 只含实给到的键；预览页必须渲满 14 变量时用同族占位值并标【占位·未判定】 |
| 没给时长或字号字重 | 只问影响结论最大的一项（通常字号或字重），一次 ≤3 问 | 仍缺就取该场景默认档并标【假设】，结论点明「随字号变化」 |
| 色觉模拟塌陷（`cvd` 报某对低于 0.10） | 先加明度差（改 L 不动色相）重跑 `cvd` | 明度差已挤压到影响层级就改用形态或文字冗余（图标、下划线、标签），写明「仅靠颜色不可区分」 |
| 要求档高于该承载面物理上限（纯白/纯黑也达不到） | 先量上限：`contrast "#FFFFFF" "<面>" --size N --weight W`（正极性用 `#000000`）；能提字号或加字重就提，把要求档降到上限内 | 不能改字号就判「该面不可承载此档」，给出该面可达最高档与差额，交用户裁：换面 / 改字号 / 带条件通过（见 thresholds 1.4） |
| `contrast` / `matrix` 不达标（exit 1） | 按缺口提字号、加字重、拉明度差或改承载面，一次只动一个变量 | 用户要求保留原值，就给「保留 + 补偿」方案（具体字号字重或承载面）并标明是带条件通过 |
| `preview` 注入失败（缺变量 / 路径不可写） | 查 token 名与模板 14 个变量是否一一对应；输出换可写目录 | 仍失败就不交预览页，改交「色值 + 判定表 + JSON」并说明原因 |
| 需求超边界（色阶 / 插画印刷 / 整套设计系统） | 说明边界并给一条替代路径（如顺序色阶改感知等步长取色），不代做 | 用户坚持就要：可算部分照算（层级、对比、色觉），不可算部分标【超出范围】，不硬套界面 token 判据 |
| `--to-hex` 三数写错位置或给少了（exit 2） | 按 `--to-hex "0.7 0.2 40"` 引号三数形式重写 | C 再大也不报错，脚本按 ×0.98 缩到入色域并标 `[超出 sRGB，色度收缩至 …]` |

## 输出契约

**快档（默认）**

1. **结论**：是否可用、最大问题是什么，一句话。

2. **决策摘要**：目标声明（含【假设】/【覆盖】/ 不可改动项）→ 意图解读 → 角色映射 → 合成层清单（token｜透明度｜落点｜实色｜最差面）→ 矩阵（标最差格，alpha 记「值 @ 面」）→ 改动表（角色｜原值｜新值｜理由｜目标）→ 保留项。
3. **场景预览页**：色值填进模板副本，浏览器直开即可看这套色在真实界面里的样子。
4. **token JSON**：可直接写回主题文件；token 命名以输入端已有命名为准，不随意增减。

生成轨另加 **候选对照表**（骨架差异 | 各自强弱 | 推荐哪套 | 取舍代价），理由须落到机制与场景，不能只说「更耐看」。

**深档（要完整报告时）**：快档基础上补全十二项实测与理由、色觉模拟、人眼验收与不确定项；13 节规范见 `references/audit-report.md`。

## 反例与黑名单（碰到就停手）

分三类：判据用错、取数用错、表达与层级用错。命中任一条即停手，按「改做」重跑；不得只口头声明已改。

**判据类**

| 别做 | 为什么 | 改做 |
| --- | --- | --- |
| 拿通用阈值套场景 | 12px 与 24px 不同，目标先行 | 先声明目标，再按字号字重查表 |
| 把「对比越高越好」当优化方向 | 上限与下限同为约束 | 暗底正文收离纯白，长文下限达标即止 |
| 把「该弱」当「读不清」，让弱化承载长句 | 弱化档只服务短标签 | 正文 / 辅助 / 弱化三档分开判 |
| 弱档达标即收工（挤到次档旁） | 下限与相邻可辨差成对，挤近等于没分层 | 达标后回头查与相邻档 ΔE |
| 深底纯白正文 / 浅底浓黑长文 | 极端对比在长阅读上出光晕 | 正负极性各设上下限，端点排除 |

**取数类**

| 别做 | 为什么 | 改做 |
| --- | --- | --- |
| 凭记忆写 APCA / 矩阵数字 | 手算必错且难察觉 | 一律跑脚本，只写跑出的数 |
| 对带 alpha 原值下结论或只测 bg | 观感由承载面决定 | 先 `composite` 到最差面，再 `matrix` 扫全面 |
| 用 `color-mix(in srgb)` 派生主题色阶 / hover / 淡底 | 同一比例跨色相的明度与彩度变化不一致 | 改 oklab 混色（`mix --space oklab`）重算再判 |
| 用 /20% 透明度表达品牌深浅 | alpha 落点不同结果就不同 | 放真实组件与最差面验，色阶用实色 |
| hover 用 brightness 兜底或没变化 | 状态反馈是 ΔE 问题 | hover / selected 至少 ΔE-OK 0.10，并验其上文字 |

**表达与层级类**

| 别做 | 为什么 | 改做 |
| --- | --- | --- |
| 光晕只看数值不看面积与时长 | 高对比贴亮底、看久了照样疲劳 | 上限随面积、时长收紧并给动作 |
| 一 token 兼两职只验一职 | 文字过了不代表图标、边界过 | 两职分别验，任一不过即不通过 |
| 在暖底或大面积上放高彩度蓝紫当正文 / 小图标 | 纵向色像差让短波小字发虚，调节负荷高 | 换承载面或改明度，别靠加对比硬救 |

## Non-Goals

- **数据可视化色阶**（顺序 / 发散 / 分类）：判据与界面 token 不同，见卡住表超边界行。
- **插画、摄影、印刷配色**：色域、纸白与油墨叠印不在判定链内。
- **品牌色相**：用户资产，只指出冲突与替代用途。
- **色彩心理学叙事**：不解释「蓝色代表信任」，只判可读性与意图保真。
- **整套设计系统**：只管配色与文字—承载面关系，不涉版式、间距、组件结构。

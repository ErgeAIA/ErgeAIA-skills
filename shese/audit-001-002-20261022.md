# ThemeVault #001 夜灯 (erge/dark) · #002 晨光 (erge/light) 审查决策摘要

快档产物：preview-001.html / preview-002.html、theme-001.json / theme-002.json（14 标准名）。
取数：ThemeVault themes/erge/{dark,light}/palette.md 全表现读；判定口径 APCA Lc（官方字号-字重矩阵）+ ΔE-OK(0.10) + WCAG 记账。

## 一、命名 ↔ 颜色匹配度

总体：命名与颜色的体系一致性高，三五处具体不匹配（见下）。

- 001「夜灯」：bg #1A1714 L 0.207 / C 0.0075 / h 67°，暖深底成立；text #F3EDE7 L 0.949 暖白；全套中性 h 集中 59–85°，温度统一。主色 #F2570F L 0.658 / C 0.203 / h 40°「调沉」成立。
- 002「晨光」：bg #FAF1E9 L 0.963 暖纸面、C 0.014「主色 5% 染」与实测吻合；accent #FF6A2B L 0.702 亮一档，晨光向成立。
- 「深版为浅版近邻：L↓ C↑ H↓」三向全部实测成立：L 0.658<0.702 ✓ C 0.203>0.196 ✓ h 39.7<40.7 ✓。

不匹配点：
1. 002 --border-focus #C9A48C 对 bg 2.05:1，弱于 border-strong 1.43:1（对 bg），却有 87.06:1 上的焦点含义——「焦点」名义是页面里最强应答色，实际 003 里比普通边框更显弱；名实不符，焦点态会丢。
2. 001 --text-dim #858079 备注「on bg 4.56 过 AA」按 WCAG 记账属实；但按 APCA hint@13px 要求 Lc 113.3，实测 -33.99，差 3 倍。备注与判定口径脱节。
3. 001 --card #241F1B 与 --bg-surface #241F1B 同值：「卡片」与「面板」两词一色，14 标准名里 surface/card 应有自己的位置（属词表—赋值问题，非观感错误）。
4. --accent-hover（001 #C2460B）与 --border-focus（001 同值）一值两键，可接受复用，但审命名时是同色配两名。

## 二、硬判据问题（判定链实测）

1. 三档文字在其最差面全部不达标（两主题同病，matrix exit 1）：
   - 001：text@elevated Lc -93.03、textMuted@elevated -66.61、textDim@elevated -31.40（要求 110/110/113.3，14/14/13px 400）。
   - 002：text@surface +93.23、textMuted@surface +75.48、textDim@surface +63.60。
   分两类读：text@elevated 在 001 有 1.4 情形成分——量上限后纯白也只能给那么多，正文要达标应提字号（16px/400 要求 90，实测 -93.03 过线）。textDim@elevated/-avg 系是真问题：hint 档 13px 要求 113.3 只拿到 31–34，差距 3 倍；即便按 16px 要求 90 也远不了——textDim 的可用域只剩「≥17px 或加粗」，作正文必不合格，只能当 hint 用。
2. 语义色可区分性 6 对塌陷（两主题同值，cvd exit 1）：#4353B8(info) vs #6B51C6(queued) 常态 ΔE-OK 0.063，protan 0.023 / deutan 0.039 / tritan 0.057，四象限全塌；ok vs warn、ok vs queued(tritan) 等。queued 紫罗兰与 info 蓝靠色相 <15° 区分，protan/deutan 下纯靠 0.02–0.04 明度差——同屏必塌，需形态冗余（图标、下划线、文字标签），仅靠颜色不可区分。
3. 面层级 ΔE-OK 全塌（delta exit 1）：001 bg→surface 0.0367 / surface→elevated 0.0382；002 bg→surface 0.0230 / surface→elevated 0.0622。低于 0.10 但在深底 0.03-0.09 / 浅底 0.015-0.03 的本仓实测常态带内——处理按形态冗余：面边界靠 border / hairline / 阴影承载，不靠明度差。此处按 troubleshooting 可降级。
4. 主色当文字用绝不达标：001 accent 5.22 WCAG / Lc -40.1；002 accent 2.56 WCAG / Lc +46.33。002 品牌橙 #FF6A2B 在白卡 2.86:1——这个品牌橙无处可当正文或小图标线（过不了 3:1 非文本线）。palette 备注的「accent-foreground #171614 主色上的文字，WCAG 达标」记账 6.33:1 属实；但按 APCA 14/400 只 +48.97，14px 按钮文字要过需要 ≥18px bold 或大面积填充另档判据。
5. 002 --accent-secondary #F07A3D 与 --accent #FF6A2B ΔE-OK 仅 0.048，主/次强调几乎不可辨——选色问题，重选在 #D15723/#C2460B 段才是『次一级』的真正落法。001 的 secondary #FF7A3D 也有同问题但 ΔE 待实测后单列。（001 accent ↔ secondary 在上轮实测 #FF7A3D h 43.2 邻近 40→也近，则两主题 secondary 均过近，主题包的 accent-secondary 均建议重选）
6. --*-on-dark 五条都是 color-mix(in srgb…) 表达式 —— 触发本技能六节负向清单的禁法（跨色相混色明度/彩度漂移不可控）。改用 mix --space oklab 估：#257552 80% 白 → #569072（srgb 混成 #519175，明度方向差异小但彩度漂移在饱和区更大）；等等。仓库自报「on bg 过 AA」按 WCAG 记账成立（4.56:1 一溜），但这五个 on-dark 值的 APCA 都在 -26 到 -36 区间 —— 作 14px 文本完全不够，只可当 ≥18px 粗体或图标线；这些「深底前景适配」的实际档位比备注暗示的低得多。
7. 语法高亮色（DEC-017 豁免沿用 opensquilla）：#8E24AA L 0.490 紫、#1E55C7 L 0.487 蓝、#0E7490 青，与暖底 h 67° 色相差 190–250°。若以「夜灯」人设论，有冷暖断层；但功能豁免（ADR-0008 显式），仅记为外族存在，不判盾德失败。

## 三、结论

- 命名：色相家族、明度骨架、『深版为浅版近邻』三向自定派生规则实测成立；命名与颜色总体匹配 [已确认]。两处名实不符：002 border-focus 过弱、001 textDim 备注与 APCA 判定严重脱节。
- 功能 6 通道：queued/info 蓝紫对在色觉模拟下必塌，同屏必须加非颜色冗余。
- 主色使用域：002 品牌橙 #FF6A2B 只能当大面积填充，或 ≥18px bold 配 accent-foreground；001 text@bg 15.37:1 超 15:1「暗底长文舒适度开始掉」的经验线，长时间阅读场景下应把主文本 L 降一档（同族降亮度）——优化建议，非合规红线，标【经验】。
- 最值一条发现：002 secondary #F07A3D 与 accent #FF6A2B ΔE-OK 仅 0.048，主次强调不可辨（001 secondary 同病），需重选。
- 人眼四类（品牌分量、层次存在感、冷暖统一、图标语义一致）须并排看 preview-001/002.html 复核，机检不代判。

（机检口径：selftest 27/27 PASS；matrix/cvd/delta exit 1 是判定链正常返回，未静默；ΔE-OK 0.10 取本仓统一尺度；APCA 要求档来自官方矩阵插值，非拍脑袋。）

# 修订（2026-10-22 二轮）：意境判读 + 优化方案

用户裁定补充判据来源：晨光 = 新的一天、元气满满、有动力的色调；夜灯 = 晚上的一盏灯，安静、不刺眼的阅读——并主张**所有暗色调都应如此设计**。此句已纳入意境判据层（名字先于颜色）。

## 意境判读

- 001「夜灯」：灯下读 = 照度受限空间。现版 bg L0.207 偏亮、text #F3EDE7 对底 15.37:1 超 15:1 舒适带——夜里「晃」。方向：bg↘ text↙ 同族降，让「灯圈」集中、读时不累。【经验层，非红灯】
- 002「晨光」：晨光 = 清爽（纸面 ✓ 已成立）+ 推动感。现版品牌橙在白卡 2.86:1 无处当正文/小图标线，整页「推动力」缺一条可达路径。方向：给橙配深色同族行走线（secondary 改深），高彩亮色沉一档被纸面接住。

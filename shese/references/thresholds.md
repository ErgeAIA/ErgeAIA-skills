# 阈值登记（数字的唯一真相源）

何时读：任何需要写出对比度、明度差、可辨间隔、面积—彩度这类具体数字之前先读本文件；SKILL.md 与其他 references 谈数字时一律指回本文件。

## 使用纪律

1. **数字是刻度，不是门禁**。每条数字都挂在一条感知机制上，是那条机制在常见场景下的默认刻度；换目标就换刻度（不可违背第 1、2、3 条）。
2. **偏离必须补偿**。任何偏离下面锚点的取值，都要写明它服务哪个目标、用什么补偿（提字号、加字重、拉开层级明度差、减小高彩度面积）。
3. **不许因为没有数字就放过明显问题**，也不许因为数字好看而牺牲目标。
4. 脚本里出现的同一数字以本文件为口径；脚本常量与本文冲突时以本文为准并修脚本。
5. **写出数字必须标来源级别**：官方标准／论文锚点／本仓一手实测／工程惯例。前两级可直接引用，后两级标【经验】并写明未验证范围；取不到来源的降级为「目标推导 + 人工判断」，不许冒充实测数。

## 一、对比度

### 1.1 判定口径：APCA Lc（SAPC APCA-W3 0.1.9 W3 · G-4g，2022-07-03）

- **唯一目标推导来源**是官方字号—字重矩阵（`fontLookupAPCA` 的 `fontMatrixAscend`，Public Beta 0.1.7 G · 2022-05-28；行 = Lc，列 = 字重 100–900，格值 = 该 Lc 下该字重的最小可用字号 px，参考字体 Barlow）。
- 因此**不给脱离字号与字重的合格判定**（不可违背第 9 条）。写法是「按官方矩阵查表」，脚本入口 `contrast` / `matrix`（内部 `apca_required_lc(字号, 字重)`）。
- 三个可手核的格点锚点（用于回归与自检，不是通用门槛）：

| 字号 / 字重 | 官方矩阵要求 |
| --- | --- |
| 16px / 400 | Lc 90 |
| 24px / 400 | Lc 60 |
| 32px / 400 | Lc 50 |

- **重要**：常见说法「长文 Lc 60 起步」是大体字档（24px/400）的刻度，**不是 16px 正文的刻度**；16px/400 按官方表要到 Lc 90。把 60 当通用正文起点即属拿通用数字套场景。
- 官方矩阵自带的三条语义注记（引用原文）：「Lc values under 70 should have Lc 15 ADDED if used for body text」「666 - this is for spot text, not fluent」「5xx - minimum font at this weight for content」。即：正文用 Lc < 70 的档位需再加 15；Lc 660 段只适合零散短字、不适合成句；Lc 500 段是该字重下承接内容的最低档。
- **无字号字重信息时**才退回角色默认下限（参考锚点档，不是硬底线）：正文 60 / 辅助 45 / 弱化 30（脚本 `ROLE_FLOOR`）。给出时必须同时标【假设】并说明「补上字号字重后结论可能变严」。

### 1.2 极性不对称

负极性（浅字深底）在细体小字下更易产生光晕，**不得与正极性套同一门槛**。官方算法已内建不对称（正负分支用不同指数与偏移），所以不要手工给正负极性加减常数；要判断的是「这个字号字重在这个极性下够不够」。

### 1.3 记账口径：WCAG 相对亮度比

- 只用于**记录与跨主题比较**（可复算、可抄给别人核对），**不进判定**。常用刻度 4.5:1 / 3:1 属记账刻度，不得当作通过线。
- 报告中与 APCA 并列出现时，必须标清哪个是记账、哪个是判定（见 `references/audit-report.md`）。

### 1.4 承载面物理上限（要求档可能无解）

- **上限**：给定一个承载面，其上任何文字色能达到的 |Lc| 有物理上界——深底上最亮是纯白、浅底上最暗是纯黑，再没有更远的可达点。
- **无解判定**：当 1.1 查出的要求档**高于该面上限**时，这个字号 / 字重在该面上**不存在达标的文字色**；问题在字号、字重或承载面，不在色彩选择。此时不得判「配色不合格」，也不得挑一个最好看的色硬判通过。
- **量法**：`contrast "#FFFFFF" "<面>" --size N --weight W`（正极性把前景换成 `#000000`）。输出的 |Lc| 即该面上限，同一命令的「要求」列即该字号字重的要求档。
- **实测例**：`#12100E` 上 `--size 13 --weight 400` 要求 |Lc| 113.33，而纯白只有 107.42（exit 1）→ 13px/400 在该面无解；同面放到 16px/400 要求降到 90.0、17px/400 降到 81.67，均可达标。
- **处置**：按 `references/troubleshooting.md` 的物理上限行——先提字号或加字重把要求档降到上限内，或换更深的承载面；都不能动时，给出该面可达最高档与差额，交用户裁决（换面 / 改字号 / 带条件通过）。

### 1.5 控件边界（非文本，合规兜底）

- 可寻址控件（按钮、输入框、可聚焦容器）的边界对紧邻面 **≥3:1**（WCAG 2.x 1.4.11 非文本对比度）。这是合规兜底，不进 APCA 舒适判定；边界不可见时用户找不到控件，属功能缺陷而非审美问题。
- 只作分界用的线（卡片分隔、表格线、区域切分）不按对比比判，按 ΔE-OK 判可辨（见 2.1）。

### 1.6 舒适上限（经验软上限，无定量文献）

- 标准只有下限、舒适要上限：对比拉满对长阅读反而带来光晕与疲劳。暗底长文的经验区间是亮度比约 **8–12:1**，超过约 **15:1** 舒适度开始下降；浅底长文避免接近纯黑（见五节）。
- **这是经验观察，不是文献阈值**：暗底亮度天花板目前没有定量文献（判据文档已明确标注该空白），引用时标【经验】，不得写成科学结论或硬底线。
- 落地方式是负向规则，不是数字门禁：深底不用纯白长文、要点档不排长段、长阅读与大面积亮字把上限收紧；面积越大、单次时长越长，上限越紧。

## 二、层级明度差

- 在 OKLCH 里比 L，不在十六进制里比。相邻层级只要「可辨」即可，深色模式通常需要比浅色更大的间隔（暗适应下明度分辨下降）。
- **可辨间隔**沿用本仓既有视觉门禁的同档数字：ΔE-OK ≥ 0.10。理由：同一仓库不应出现两套可辨性尺度（本仓既有视觉技能已用 0.10 作四态可辨门禁），本技能取同一档以便跨技能核对。
- 层级跨度不只有「可辨」一个要求：正文与底之间还要过 1.1 的矩阵档。
- **多级阶梯通常达不到 0.10**：面层级（bg → surface → card → elevated）的相邻 ΔE-OK 实测多在**深色 0.030–0.092、浅色 0.015–0.031**（深色：VSCode Dark+ `#1e1e1e`→`#252526`→`#2d2d30` = 0.0299 / 0.0336，GitHub dark `#0d1117`→`#161b22`→`#21262d` = 0.0440 / 0.0464，Tailwind slate dark `#0f172a`→`#1e293b`→`#334155` = 0.0720 / 0.0922；浅色：Ant Design `#ffffff`→`#fafafa`→`#f5f5f5` = 0.0149 / 0.0150，Tailwind slate light `#ffffff`→`#f8fafc`→`#f1f5f9` = 0.0162 / 0.0163，GitHub light `#ffffff`→`#f6f8fa`→`#eaeef2` = 0.0221 / 0.0312；OKLCH ΔL 与 ΔE-OK 近似相等）。因此 0.10 对多级阶梯是**偏高的锚点**，不是「做不到就不合格」；深色阶梯的起步落点与级数推导见 `references/generate.md` 3.1。
- **达不到时的补偿**：允许用边框或分隔线建立可辨（`delta` 对边框与相邻面仍须 ≥ 0.10），结论须写明「层级靠边框而非面色差建立」，不得静默放过。

### 2.1 纯分界（只表示边界，不承载信息）

- 卡片分隔线、表格线、区域切分这类线不按对比比判：可辨区间约 **ΔE-OK 1.1–1.5**，低于 1.1 视为「设了等于没设」，高于 1.5 则边界本身开始抢注意力。
- 该区间来自判据文档整理，尚无本仓跨主题实测样本，引用时标【经验】；控件边界（可寻址）走 1.5 的 3:1，不按本条。

### 2.2 状态反馈

- hover / selected / focus 与被替换状态色之间至少 **ΔE-OK 0.10**，并验其上文字仍达标；不许用 brightness 变化量或「看起来变了」代替。
- 状态色同时承文字时，两职分别验（不可违背的一 token 两职条）。

## 三、色觉可辨（硬底线）

- 判据：同一组承担语义区分的颜色，在常态与 protan / deutan / tritan 三类模拟下的 ΔE-OK 都不得低于 **0.10**（脚本 `cvd --min-delta`，默认 0.10，取 severity 1.0 的全色盲最坏情况）。
- 任一模拟下低于该值即视为**塌陷**，处置优先级：先补明度差，再补形态或文字冗余编码；不得只靠色相区分（不可违背第 10 条与判定表「语义色可区分性」）。
- 常态自身低于 0.10 同样报——那是连正常色觉都难分的组。
- 模拟口径：protan / deutan 用 Viénot 1999 单矩阵，tritan 用 Brettel 1997 双半平面（按分离面法线选面）；矩阵原文在 `scripts/shese.py` 的 `CVD_VIENOT` 与 `CVD_BRETTEL_TRITAN`。

### 3.1 实测约束：四色语义集合很难只靠色值过线

- 深底（bg #131211）上按 OKLCH 明度阶梯做网格搜索（L 0.45–0.95、C 0.13，四色色相固定为绿 145° / 黄 85° / 红 30° / 蓝 245°，另在 L 0.66–0.94 / C 0.08–0.14 细化）：四色组合的「最弱对 ΔE-OK」上限约 **0.134–0.145**，且拿到它的组合必须把某一色推到 L 0.94–0.95（近白淡色）；落在常见审美区间（L 0.66–0.90）的组合上限约 **0.09–0.10**。
- 四色集合的最弱对**几乎总是「成功 × 警告」在 deutan 下**（绿黄在绿色盲下最难分）；三色集合（成功 / 警告 / 错误）同样是这一对。
- 权威源也过不了：ThemeVault `#046 kanagawa/dragon` 的 ok #98BB6C 与 warn #FF9E3B 在 protan 0.050、deutan 0.077（常态 0.157）。
- 因此本文件把 0.10 定为**色值层的严格门禁**：达不到时先做明度阶梯（优先拉开成功与警告，OKLCH L 跨度 ≥ 0.12），再叠图标或文字冗余。`cvd` 的产出是「哪一对最危险」，不是「这套色不能用」；判定表「语义色可区分性」要的是「明度差**或**形态、文字冗余」，两者取其一必须成立。
- 实测一组过线档（深底 #131211，C 0.08–0.14）：成功 L 0.90 / 警告 L 0.84 / 错误 L 0.72 / 信息 L 0.71 → 最弱对（成功×警告，deutan）0.100，bg 上 |Lc| 分别 −88.4 / −74.1 / −50.3 / −52.1。

### 3.2 门禁组成员怎么定（哪些色必须进 `cvd`）

- **入组判据只有一条**：该色是否**承担需要被区分的语义**。判据不按时长、不按名气、不按它在 token 表里的位置。
- **默认在组内**：`success` / `warning` / `danger` / `info` 四个状态色（它们的存在意义就是被区分）。
- **默认不在组内**：`brand` / `accent`（品牌与点睛表达情绪，不承担状态区分），以及单纯的面层级色。
- **例外**：`accent`（或 `brand`）若与组内某色**在同一界面上并列承担状态**——例如主按钮与危险按钮并排、强调色同时充当「进行中」状态——则按「使用对」入组，只判它与那一色的可辨性，不把整个品牌色系拖进来。
- **入组后的过线方式**：先补明度差；明度差已挤压到伤层级时，允许「明度差 + 形态或文字冗余（图标、下划线、标签）」组合成立，判「带条件通过」，并在结论里点名冗余形式。只靠色相区分永远不算过。
- **未入组的色**也要在报告里说明它是按哪条判据免检的，不许默不作声。

## 四、面积与彩度（无通用数字，给方向与判据）

- 关系是方向性的：**面积越大，可承受的彩度越低**；高彩度留给小面积点睛。
- 本项**没有可套用的通用百分比**。判定方式：在 OKLCH 里看 C 的实际取值，同时看该色覆盖的面积占比与它是否与正文争夺注意力；具体刻度由场景推导（见 `references/scenes.md`）。
- 只有一条硬约束：高彩度色的面积必须显著小于承载阅读的面积（否则它与正文抢注意力，属判定表「高彩度色的面积」锚点被击穿）。
- **品牌与点睛铺开时的面积经验上限约 10%**：超过后与正文争注意力、久看疲劳。依据是工程惯例 60-30-10，无 HCI 实证，标【经验】；超出时改中性面衬底、品牌留点睛，不靠调低品牌彩度硬压。

## 五、深浅模式基础色（硬底线）

- 深色模式不用纯黑 `#000000` 作大面积底色；浅色模式不用纯白 `#ffffff` 作正文色。这是「排除端点」，替代取值由阅读环境与时长推导（暗适应、浦肯野效应、光晕与眩光）。
- 同一条也管高对比极端：正负极性都避免「纯白贴纯黑」的长文组合。

## 六、透明度与合成（无阈值，只有口径）

- 带 alpha 的**文字 token 必须声明最差承载面**；对比结论以该面上的合成实色为唯一依据，未声明基准面的数字视为无效（不可违背第 6 条）。
- 合成口径 = 浏览器行为：在 **sRGB 空间**逐通道混合，多重叠加沿整条链算；设计工具在线性空间混合时结果不一致，以浏览器渲染为准并注明口径。
- alpha 解析：`#rgb` 三位展开 nibble；`#rgba` 四位 alpha = nibble/15；`#rrggbbaa` alpha = byte/255。
- **模板自带的混色底一并判**：预览模板（`assets/scene-preview.html`）的派生底（按钮、状态徽章、选中行、遮罩）用 `color-mix(in oklab, …)` 或 alpha 叠加。凡有文字落在其上，都先算出实色再进矩阵取最差面：oklab 混色用 `mix A PCT B` 或浏览器实算，纯 alpha 用 `composite`；不得因为「这是模板的东西」就跳过。
- **派生色阶禁用 sRGB 混色**：同一混色比例跨色相混出的明度与彩度漂移不一致，hover / elevated / 淡底 / 边框阶一律在 oklab 里混；被审主题若用 `color-mix(in srgb, …)`，判为缺陷并给 oklab 替代值与重算后的判定。
- **合成基准面**：模板底若压在某个 token 面上，基准面就是那个 token 面（如徽章底压卡面，写 `#1f2a1a @ card`），不是页面最底。
- 报告中每个带 alpha 的结果记作「值 @ 面」，例如 4.8 @ card。

## 不确定项

- 官方矩阵只给格点，格点之间为**线性插值**（脚本做法）；官方未规定插值方式，故格点值精确、格点之间为近似。
- 「可辨间隔 0.10」源于本仓既有视觉门禁档，而非色彩学界的统一阈值；沿用是为了全仓一致，不代表它是普适常数。
- 3.1 的上限数据来自**单个深色底（#131211）与固定四色色相**的网格扫描，不是全色域结论；换底色、换色相或改彩度预算需重扫，不得直接引用上限数字。

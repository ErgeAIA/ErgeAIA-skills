# 设色 · Shese

> 设色者，布色于位，明其阶次。先定其所用，再正其所失。

**v1.1.0** · Agent Skill ｜ 配色审查、优化与生成

在用户声明的阅读场景下，让一套配色读得舒服，同时不丢失它原本要表达的情绪——并且让不懂色彩学与设计的人也能拿到结论、看见这套色在真实界面里的样子。

## 解决什么

配色问题通常不是「不好看」，而是「读起来累、层级分不开、语义色混在一起」。凭感觉调色会反复摇摆，因为判断依据散在色相、明度、彩度、透明度、字号和环境亮度里，而这些量互相耦合：高彩度色自带更高的感知亮度，带 alpha 的颜色没有固定观感（最终色由它落在哪个面决定），同一组色值在 12px 与 20px 下不该得出同一结论。

设色把这件事拆成一条可复算的链：先声明阅读目标（用途、时长、环境亮度、字号字重、信息密度），再由目标反推尺度；在 OKLCH 这类感知均匀空间里比明度和彩度，而不是直接比十六进制；把带 alpha 的颜色沿叠加链合成到实色后再判定；最后按感知机制逐项给结论，而不是套一组通用数字。

产出不是「通过 / 不通过」，而是**结论 + 区间 + 推荐点 + 取舍代价**：多数问题存在合理区间，选哪一点由你的目标决定。

在技能目录下（`scripts/shese.py` 的父目录）执行：

```bash
# ① 一条配对：给字号字重，按 APCA 官方矩阵查起步档
python scripts/shese.py contrast "#8b949e" "#0d1117" --size 16 --weight 400
```

```text
文字 #8b949e  承载面 #0d1117
WCAG 相对亮度比 6.15:1（记账口径，仅供跨主题复算）
APCA Lc -43.58（判定口径）
角色 body  要求 |Lc| >= 90.0  [目标推导（官方字号-字重矩阵）]
结论：不通过 —— 需补对比或提字号/加字重/改承载面
```

[已运行验证] 输出为实跑原文；退出码 1 = 判定不达标（不是命令失败）。

```bash
# ② 把整套 token 注进模板，生成可直接在浏览器打开的填色副本
```

## 怎么用（场景 × 示例提示词）

两条轨道共用同一条判定链。下表每行都是你会对设色说的话：

| 能力 / 场景 | 一句话方法 | 示例用法提示词 |
| --- | --- | --- |
| 审查一套现有配色 | 贴色值 + 说清用途与阅读条件 | `帮我看看这套：bg #101014、surface #16161D、text #E8E6E3、accent #ff6a2b。深色，代码编辑器，长时间读。` |
| 一句话生成配色 | 说风格 / 症状词 + 场景 + 禁忌 | `给我一套深色、安静、偏冷、适合长时间读代码的配色，不要紫色。` |
| 按参考主题适配 | 给主题编号或主题名 | `按 #048 kanagawa/wave 的色板，做一版网页长文阅读用的。` |
| 只要看到效果 | 明说做预览页 | `把这几个颜色做成预览页，我要直接看效果。` |
| 深档完整报告 | 明说要完整报告 | `出一份完整报告：这套色在移动端卡片流上有什么问题。` |
| 深浅都要 | 明说深浅对照 | `深色优先，同时给我浅色对照。` |
| 换字号 / 换场景再判 | 给新的阅读条件 | `同一套色，按 12px 细体正文重判一次。` |
| 边界：数据可视化色阶 | 热力图、地图、多类别图表配色不归设色 | `给热力图配色。`（设色不做，需另立判据） |

## 它怎么工作

```text
声明阅读目标 → 还原语义角色 → 展开 alpha 合成 → 按机制判定 → 最小改动优化 → 出预览页与 token
```

- **审查轨**：用户给既有配色（十六进制列表或语义 token）+ 场景 → 判定 + 最小改动优化。
- **生成轨**：用户给一句风格意图、症状词或参考锚点 → 2–3 套**结构不同**的候选（不是只换色相）→ 走同一条判定链逐套验一遍。

判定分三级标注：**硬底线**（违反即不通过，只覆盖直接破坏阅读或造成误读的部分）／**参考锚点**（通用默认起点，可浮动，浮动须给理由）／**目标推导**（由阅读目标直接算出，不同目标必然得出不同结论）。

## 命令速查

`python scripts/shese.py <子命令> --help` 看完整参数。退出码统一为 0 = 成功（判定类子命令即全部达标）／1 = 判定不达标／2 = 输入或环境错误。

| 子命令 | 用途 | 关键参数 |
| --- | --- | --- |
| `oklch` | 十六进制 ↔ OKLCH | `--to-hex "L C h"`、`--json`；超色域自动按 ×0.98 逐步收缩色度并标注，h 偏移超过 10° 时回原值交付并注明超出 sRGB |
| `contrast` | 单对配色的 APCA Lc 与相对亮度比 | `--size` + `--weight` 走官方矩阵；不给则按 `--role body\|aux\|hint` 档（60 / 45 / 30） |
| `composite` | 带 alpha 的颜色沿叠加链在 sRGB 空间合成 | `--on` 指定最底不透明基准面（只收一个，重复给取最后一个） |
| `matrix` | 文字 token × 承载面矩阵，标出最差面 | `--tokens` 里 text 条目可写 `{"hex","role","size","weight"}` 逐 token 定要求 |
| `delta` | 相邻层级的 ΔE-OK，专判层级明度差 | `--min-delta`（默认 0.10） |
| `cvd` | 三类色觉模拟 + ΔE-OK 可辨性 | `--min-delta`（默认 0.10） |
| `preview` | 把 token 注入模板生成填色副本 | `--tokens name=HEX`、`--out`、`--mode dark\|light` |
| `selftest` | 官方测试向量锚定自检 | 改脚本后必跑 |

起步档由脚本按 APCA 官方字号—字重矩阵查表得出，禁止自行插值或凭记忆给数；脚本给单点判据，交付里仍要连区间与取舍代价一起给。token 名支持 `bg-surface`、`text-muted`、`ok`、`warn`、`danger` 等常见别名，输出一律归一到 14 个标准名。

## 交付什么

| 档位 | 产物 | 用途 |
| --- | --- | --- |
| 快档（默认） | 结论 + 决策摘要 + 场景预览页 + token JSON | 直接看效果、直接改主题文件 |
| 深档 | 完整报告（补全十二项判定实测、色觉模拟校验、人眼验收、不确定项） | 需要交代依据、评审或归档时 |

场景预览页是色值的填色副本：色板 + 三级文字层级 + 深浅双模式 + 三档字号 + 三色觉模拟（protan / deutan / tritan）+ 对比矩阵并标出最差格。页面外壳用 ThemeVault 的 #001（暗）/ #002（亮）品牌主题，**被审的只有你注入的那套 token**。

## 设计依据

- **感知均匀空间**：OKLCH / CIELAB 里比明度与彩度，层级主要靠明度差建立，色相承担分类与情绪。
- **对比度**：报告沿用 WCAG 相对亮度比（可复算、可跨主题比较），判定叠加 APCA（更贴近实际阅读，且随字号字重变化）与极性、空间频率、光晕等机制。
- **透明度与合成**：合成后实色才是判定对象；带 alpha 的文字 token 必须声明最差合成面。
- **面积与彩度**：面积越大可承受的彩度越低，高彩度留给小面积点睛。
- **色觉差异**：语义色必须同时具备明度或形态冗余编码，三类模拟下仍可区分。

## 边界

- **不做数据可视化色阶**：顺序色阶（连续量，需感知空间等步长）、发散色阶（需中点中性且两臂对称）、分类色（受可快速命名色相数上限约束）的判据与界面 token 判据不同。
- 不做插画、摄影、印刷配色。
- 不替用户改品牌色相；若品牌色造成可读性问题，只指出并给替代用途。
- 与 banxin、ThemeVault 无代码依赖：计算层按公开标准独立实现，ThemeVault 只作为可选取色来源（见 `references/theme-source.md`）。

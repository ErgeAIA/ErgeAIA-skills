# 槽位模型

图标的意义由**槽位**决定，不由图形字面决定。`link-2` 放在「共享引用」是状态（两个位置指向同一份数据），放在「定位库」是动作（点一下跳过去）。同一个图形跨槽使用，用户就得先猜它能不能点——这是徽章系统最常见的隐性成本。

所以先定槽位，再谈选哪个图标。槽位定错，后面再准也是错的。

## 判定顺序

```
它是数字吗？ ──是──> 计数槽（除非数字本身就是判定结论，如「缺 1」）
   │否
点它会发生事吗？ ──是──> 导航槽（去别处）/ 动作槽（就地执行）/ 筛选槽（改变当前视图的过滤）
   │否
它是结论吗（对/错/待定/缺失）？ ──是──> 状态槽
   │否
它是事实吗（从哪来/属于谁/什么类型）？ ──是──> 来源槽
```

三条边界最容易判错，单独记住：

- **「缺 1」是计数还是状态？** 计数槽显示数量（`file-stack` + 3），状态槽显示结论（`file-x`）。「缺 1」两者都占：若它驱动用户行动（去补齐），按状态处理并用纯图标；若只是告知规模，按计数处理。**同一列表里不要两种都用**。
- **筛选不是状态**。筛选图标的开合态靠颜色/底色区分，语义是「当前视图按它过滤」；状态图标描述数据本身。把筛选图标当成状态读，用户会以为数据有问题。
- **来源不是判定**。来源是事实陈述（本地、来自仓库、来自外部链接），不表达好坏。给它加边框、底色、判定色，等于把事实升格成结论，会和真正的状态标记抢注意力。

## 状态槽

**回答**：这份数据现在是什么结论？

**形态契约**：纯图标 + 主题化 Tooltip；尺寸按 profile 的 `icon-status`（常见 16 或 18）；无边框、无底色、无常显文字；状态色只上图标本身（`currentColor` 或语义令牌）。

**允许**：图标 + Tooltip 配对固定（同一图标全站同一句 Tooltip）；同一行多个状态图标按严重度排序，最多 3 个，超出折叠进详情。

**禁止**：带边框、带底色、带文字胶囊；用动作语义图标表达状态（`download` 表达「未安装」会读成「去下载」）；用错误语义表达正常状态（`unlink` 表达「本地」）。

**反例**
| 写法 | 读起来是 | 问题 |
| --- | --- | --- |
| 边框胶囊里写「已具备」 | 一个可点的标签 | 判定被做成按钮形态 |
| `cloud-off` 表示「本地插件」 | 断网了/掉线了 | 错误语义污染正常状态 |
| 红色 `circle-check` 表示「已具备」 | 出错了 | 色与义冲突 |

## 来源槽

**回答**：它是从哪来的、属于哪一类？

**形态契约**：纯图标 + Tooltip；尺寸通常比状态图标低一档（profile 的 `icon-source`，常见 16）；中性色（`text-muted`），**不用**状态色；与相邻状态图标保持间距（`gap 8px` 量级），避免被读成同一簇判定。

**允许**：本地/仓库/外部/内置 这类离散来源；来源图标可以与名称同列，但不得与判定图标合并成一个「复合徽章」。

**禁止**：加边框或底色；用状态色；用表达「断开/失效」的图标（`unlink`、`cloud-off`、`wifi-off`）——来源是正常属性，不是异常；用动作图标（`folder-input` 会读成「导入」）。

## 计数槽

**回答**：有几个？

**形态契约**：图标 + 图标外侧数字，水平并列，同一点击区；数字最多两位，超过显示 `99+`；判定计数（如失败数）用状态色一色到底；非判定计数用中性色。**不做角标**（图标右上角的红点/小圆），角标在密集列表里既看不清又会和状态色打架。

**允许**：`file-stack` + 3、`history` + 12；计数与图标之间 `gap 6px`。

**禁止**：数字放进图标内部；角标形态；同一行既有角标又有状态图标；计数带边框（那就是文字胶囊了，计数不是胶囊）。

## 筛选槽

**回答**：当前视图是否按这个条件过滤？

**形态契约**：纯图标按钮，尺寸随控件（工具条 16/36，行内 16/36）；开合态**只改颜色或底色**，不换图形——换图形会让用户以为功能变了；开态必须有 `aria-pressed`。

**允许**：`circle-arrow-up`（只看可更新）、`list-filter`、`star`（只置顶，不挂计数）。

**禁止**：开合两态用两个不同图标；把筛选开关做成状态图标（用户会以为那是数据状态）；筛选图标挂计数角标。

## 动作槽

**回答**：点一下会发生什么？

**形态契约**：纯图标按钮 + Tooltip；图标 16px，热区不小于 36px（行内密集场景按 profile 的 `hit-control`，不得低于 24px 且必须在 profile 里写明例外）；hover 才显形时保留占位，避免行宽跳动。

**允许**：打开/定位/复制/移动/删除/安装/更新/分析……；破坏性动作（删除、清除）用两段式确认，不用颜色作为唯一提示。

**禁止**：用动作图标表达状态（`download` 当「未安装」）；热区小于 24px；同一行超过 6 个动作图标（改成溢出菜单）；纯图标动作没有 `aria-label`。

## 导航槽

**回答**：点它会去哪？

**形态契约**：图标（可选配文字标签）；主导航 18/40，次级导航 16/36；与动作槽的区别是**改变位置**而不是**改变数据**。

**允许**：导航图标可带文字，因为「去哪」是长尾信息，文字比图形更省认知。

**禁止**：导航图标放进数据行冒充状态；同一个图标在导航和动作里混用（`link-2` 尤其危险）。

## 跨槽混用的处置

发现一个图标要同时承担两种槽位时：

1. **优先拆**：拆成两个元素（状态图标 + 动作按钮），各自带自己的 Tooltip。
2. **不能拆则降级**：保留信息量更大的那个槽位，另一个改用文字或在 Tooltip 里说明。
3. **记录**：在 profile 的 `conflicts` 登记，写明「两种读法各自导致什么误操作」，交给规范所有者裁决，不要自行拍板。

## 自检

- 这个槽位的形态契约（边框/底色/文字/尺寸/可点）是否被违反？
- 图标语义是否属于本槽？把它的字面意思读出来，会不会得到另一个槽位的动作？
- 同排是否已有别的槽位图标，颜色与尺寸是否形成了不该有的层级？

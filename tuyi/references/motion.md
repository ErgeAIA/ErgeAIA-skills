# 动效

动效是对状态变化、任务过程或操作反馈的时间性表达，**不是装饰**。它只能强化既有语义，不能创造或替代语义；静止时也必须能理解信息。

本文件只定义通用判定。项目是否允许动效、用哪些令牌、哪些场景已批准，一律由 profile 的 `motion` 块承载（见 `profile.md`）；未批准的建议只进报告，不写成规则。

## 一、静态是默认值

按顺序过，任一答「否」就停在静态：

1. **有真实状态变化吗？** 没有变化、只是常显 → 静态。
2. **变化来自真实任务过程吗？** 任务不存在、只是按钮可点 → 静态。
3. **有真实操作反馈吗？** 只是「图标可以动」→ 静态。
4. **有明确停止条件吗？** 说不出何时停 → 静态。
5. **静态等价能表达吗？** 能（换图形、换色、加文字、Tooltip）→ 优先静态。

「静态，不建议添加」是完整结论，必须能直接写进选型卡，不要为了字段完整硬填参数。

## 二、六种形态

只讨论以下六种，不新增类别。

| 形态 | 表达 | 允许条件 | 禁止与误读 | 停止 | reduce 降级 |
| --- | --- | --- | --- | --- | --- |
| **旋转** | 时长未知的进行中 | 绑定真实任务生命周期；图标本身表示「正在跑」 | 禁用 ≠ 处理中；已知进度用真实进度；来源/状态/收藏/普通加载不旋转 | 完成 / 失败 / 取消 / 卸载 | 静态忙碌图标 + 文字或 `aria-busy` |
| **脉冲 / 心跳** | 持续存活或连接心跳 | 真实心跳、连接探测；同一时刻单个 | 普通处理中、收藏、可更新不套用；多元素同时脉冲；暗示持续耗能 | 连接稳定 / 任务结束 | 静态状态色 + 文字 |
| **扫描线** | 扫描 / 识别 / 比对进行中 | 只动图标内部扫描线；子路径可稳定定位 | 整枚旋转或位移冒充扫描；静态搜索按钮不加 | 扫描结束 / 取消 | 静态扫描图标 + 进度文字 |
| **呼吸** | 持续未读 / 告警的注意力提示 | 静态信息不足以表达优先级，且同屏预算允许 | 持续未读 ≠ 必须呼吸；同屏多个呼吸；正常或成功状态 | 已读 / 已处理 / 消失 | 关闭循环，保留静态色与图标 |
| **描边绘制** | 一次性成功 / 失败 / 校验 / 复制反馈 | 只播一次，不循环，不在每次 render 重播 | 循环、加载、状态常显 | 动画自然结束 | 即时显示完整描边 |
| **抖动** | 输入校验失败 | 目标为输入容器；一次；错误文案为主 | 图标本体抖动；每次输入重复；非输入场景 | 一次性结束 | 静态错误色 + 文案 |

### 旋转

- 只表达「不知道要多久」。已知进度（有 done/total）用进度条，不用图标转圈冒充。
- 长任务的全局进行中反馈优先走项目既有的不定态进度条机制，而不是给每个图标加旋转。
- 禁用、不可点、加载中三者不能互相替代：禁用是能力状态，不是运行状态。

### 脉冲 / 心跳

- 持续脉冲容易被读成「任务在跑」或「设备在耗能」，只在连接/存活语义成立时使用。
- 一次性反馈不要做成持续脉冲；收藏这类布尔状态保持静态。

### 扫描线

- 目标是图标**内部**的扫描线，不是整枚图标的旋转或位移。
- 先确认 SVG 内部有几何独立、可稳定定位的子路径；依赖 DOM 顺序或复杂重绘时，直接建议静态并说明代价。
- 扫描进行中优先改 `aria-label` 并禁用，是否允许内部线动画由项目裁决。

### 呼吸

- 持续存在的未读或告警，不自动意味着需要持续提醒；先问静态信息是否已经足够。
- 同屏最多一个呼吸；多个元素同时呼吸会让整屏像故障。
- 装饰性循环默认应处于暂停态，交互或真实状态触发后才运行；「持续提醒」与此冲突时必须登记待裁决。

### 描边绘制

- 只用于一次性反馈，不循环、不在每次 render 重播。
- `stroke-dashoffset` 不属于 transform/opacity 的合成层路径，与「优先 transform/opacity」存在技术冲突：作为例外登记，说明绘制成本，验证长时间列表与低端设备，并提供 reduce 关闭。
- 多节点图标要指定具体子路径；子路径不稳定时改静态。

### 抖动

- 动画目标是输入容器，不是图标本体。图标只切换到错误语义色，不抖。
- 抖动承担的是「操作被拒」的即时反馈，错误文案仍是主要信息；不要每次输入都重复震动。

## 三、动画目标与子路径可控性

每个动效必须写清目标是三者之一：

1. **整枚图标**：适合旋转、脉冲；要求图形语义本身就是过程。
2. **SVG 内部子路径**：适合扫描线、描边绘制；要求该路径几何独立、可稳定选择。
3. **输入容器**：适合抖动；图标不承担位移。

子路径判据：

- 单 path 图标可直接做描边绘制。
- 多节点图标要指出具体节点（按几何特征，不按 DOM 顺序）；节点数与几何都要在真实图标数据里核对。
- 图标库版本与项目安装版本不一致时，路径结论必须标注版本，不能跨版本推断。
- 找不到稳定子路径 → **静态**，不写「大概可以」。

## 四、参数口径

- 时长、缓动、次数、延迟**只能引用项目令牌**，不写裸毫秒。
- 项目没有对应令牌时，给出的是 `proposal`（候选），不是规则；报告里注明「需新增令牌」。
- 优先 transform / opacity；避免触发布局与大面积绘制的属性。
- 循环动画必须有触发条件、终止条件和暂停机制；不得加载即播、滚动触发、页面常驻。
- 入场、短时反馈、持续状态、主任务四类预算分开算，不合并成一条。

## 五、无障碍

- `prefers-reduced-motion: reduce` 下：关闭非必要动画，或替换为无位移的即时切换；关键状态变化可保留无位移淡入。
- 减少动效令牌通常只覆盖 transition；keyframes 要显式 `animation: none` 或等价关闭，不能只靠把 transition 时长改成极小值。
- 静止时必须仍能表达状态：图标语义、颜色、文字、`aria-*` 至少有一组独立于动画的编码。
- 进行中状态用 `aria-busy`；不要把唯一信息放进动画。
- 闪烁频率不超过 3Hz（WCAG 2.3.1，AA）。
- WCAG 2.2 SC 2.3.3「Animation from Interactions」是 **Level AAA**，只覆盖交互触发的 motion animation，不能写成 AA 的通用强制要求；项目可以把「动效可关闭」作为自身 AA 基线，这是项目要求，不是 SC 2.3.3 的等级。

## 六、运行时验证

机器检查只能查静态选择器、属性和期望值，**不能判断状态生命周期、语义必要性、任务结束后是否停止**。这些是 `human_check`，运行时用浏览器验证：

1. 打开真实页面，分别以 `reducedMotion: 'no-preference'` 与 `'reduce'` 运行。
2. 触发真实交互（开始、成功、失败、取消、卸载）。
3. 读 `document.getAnimations()`：任务结束后不应有遗留的无限循环；reduce 下非必要动画应为空或即时结束。
4. 读计算样式：`animation-name`、`transition-property`、`animation-play-state` 是否符合规则与预算。
5. 截图核对：16px 真实尺寸、浅/深主题、静态关闭动效后仍可读。
6. 没有浏览器环境时：给手工验证清单，标「运行时未验证」，不得只 grep 到 `prefers-reduced-motion` 就宣布通过。

## 七、选型模式（A）输出 7 字段

只有场景涉及真实状态变化、任务过程或操作反馈时才填；否则写「静态，不建议添加」。

1. **动效结论**：静态 / 六形态之一 / 待裁决
2. **动画目标**：整枚图标 / SVG 子路径 / 输入容器
3. **语义与触发事件**
4. **参数来源**：令牌名；无令牌则标 proposal
5. **停止条件**
6. **reduce 替代反馈**
7. **项目是否允许落地**：引用 profile 的 `motion` 状态与出处

## 八、审查模式（B）9 项

每条都要给 `file:line`、规则来源、实际行为、误读风险、最小改法、严重度：

1. 是否把动作误做成状态动画，或把状态误做成动作
2. 是否对应真实状态 / 任务 / 反馈
3. 触发事件是否真实且唯一
4. 目标是否正确（整枚 / 子路径 / 容器）
5. 循环是否有终止条件，是否加载即播
6. 完成、失败、取消、卸载时是否停止
7. 是否超项目预算（主动画并发、连续动画、入场时长）
8. 时长 / 缓动 / 次数是否来自项目令牌
9. reduce 是否降级，静态时是否仍可理解

严重度：语义误读 → blocker；预算 / 令牌违约 → major；一致性打磨 → minor；源码不足 → `N/A`；运行时不可验证 → `needs-review`。

## 九、与 profile 的边界

- 项目动效规则进 profile 的 `motion` 块，不进图标 `mappings`。
- `locked` 只用于已批准场景；`proposal` 与 `pending` 不得写成规则。
- 无法静态检查的生命周期、语义、预算条款写进 `human_checks`，由审查模式转成人判清单。

## 自检

- 是否先给了静态结论，再谈动效
- 每条动效都有真实触发、目标、停止条件
- 参数有令牌来源；裸毫秒只标 proposal
- 子路径可控性有真实节点证据与版本
- reduce 降级与静态等价都写了
- 没有把未批准建议写成项目规则

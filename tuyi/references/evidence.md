# 证据

结论的说服力不来自语气，来自**别人能不能照着复核**。本技能只认三类证据，给不出就写「未验证」。

## 三类证据

### 1. 规范原句

格式：`路径:行号 —— 原句（截断用 …）`

```
docs/design/iconography.md:31 —— 来源标记·本地插件＝hard-drive 16px/--text-muted，Tooltip 固定「手动安装，未关联仓库」
```

要求：能贴就贴原句，不要转述；转述会被当成你的解释，而不是规范的要求。找不到原文时写「规范未覆盖」，不要用「按惯例」补。

### 2. 图标库事实

格式：`id —— tags 命中词 —— 许可 —— 版本`

```
hard-drive —— tags: storage, disk, server, memory —— ISC —— lucide 1.67.0
```

要求：tags 必须来自真实目录（`scripts/iconlab.py search` 的输出），不许凭印象写；许可与版本要能指到 `data/lucide-catalog.json` 的 `source` 字段。

**反例**：写「hard-drive 的 tags 里有 local」——若目录里没有，这句话就是编的，整条结论的可信度归零。

### 3. 视觉度量

格式：`指标 = 数值（口径）`

```
16px 剪影 IoU(hard-drive, folder-input) = 0.41
16px 剪影 IoU(folder-input, folder-open) = 0.83（高混淆）
ink ratio: hard-drive 0.19 / folder-input 0.27（同排密度差 42%）
```

## 度量口径

### 剪影 IoU

定义：把图标在该尺寸下的**描边**栅格化为二值剪影，两两求交并比。

- 视口：图标尺寸（16/18/20/24）+ 少量内边距，按 `viewBox 24` 等比缩放
- 描边：按 `stroke_width` 渲染（默认 2.25，随尺寸缩放），不填充——徽章图标是线稿，填充版度量不作数
- 采样：8× 超采样后降采样，避免细线整像素丢失
- 阈值：**IoU > 0.75 视为高混淆**（启发式，来自「16px 下两枚图标轮廓重叠超过四分之三时，人眼主要靠内部细节区分」的经验；不是物理定律，报告里要写明这是启发式）

IoU 只回答「像不像」，不回答「会不会混」——会不会混还要看语义距离。`package` 与 `package-open` IoU 很高但语义只差一个字，混了后果轻；`link-2` 与 `unlink` IoU 中等但语义相反，混了后果重。**两个都报，别只报 IoU**。

### 墨量比（ink ratio）

定义：剪影像素数 / 视口像素数。

用途：判断同排图标的视觉重量是否一致。同尺寸下墨量差 > 30%，扫视时会形成假层级（重的那个被当成更重要）。这也是「来源图标要压一档」的量化依据。

### 灰度与对比度

用途：验证「状态不只靠颜色」（无障碍与色弱场景）。

- 把页面切到灰度，状态图标之间、状态与来源之间是否仍可区分
- 文字徽章的底色与文字对比度按 WCAG 正文标准核（4.5:1，大字 3:1）
- 判定色在灰度下若塌成一个灰，说明形状区分度不足，必须换图形而不是加深颜色

### 行上下文

单看一枚图标说明不了问题。必须给：

- 同一行 3–6 个真实邻居（保持真实间距、真实对齐）
- 真实尺寸（禁止放大到 24px 再对比 16px 的结论）
- 两种背景（浅/深），因为描边在深色下会显粗

## 盲测

目的：证明「见之知意」不是设计者自己的错觉。

设计：

1. **留出集**：8 行，覆盖六个槽位，不包含在推荐过程里用过的例子
2. **被测者**：没参与设计的人（第三方），只给 16px 图标 + 一行上下文（如「本地插件 · 已安装 · 3 个文件」），让他用一句话说这枚图标什么意思
3. **判分**：语义命中即算对；说出相反意思算错；说不出算未命中
4. **门槛**：≥ 7/8；任一槽位错两个以上，回炉
5. **记录**：把错误答案原样写下——错误答案比正确率更有信息量，它告诉你图标被读成了什么

**回归集**：profile 里 `locked` 的每条映射，逐条渲染并与规范原句核对。规范改了但回归集没改，说明 profile 没升版。

## 证据的写法

每条结论后面跟一行证据，形如：

```
首选 hard-drive。
证据：
- 规范：docs/design/iconography.md:31 指定 hard-drive 为本地来源标记，16px/--text-muted
- 库：hard-drive —— tags storage/disk/server —— ISC —— lucide 1.67.0
- 度量：16px IoU(hard-drive, folder-input)=0.41；ink 0.19 vs 同排 git-fork 0.21（密度一致）
```

三条齐了才算完整；缺一条就写「缺 X，未验证」——**不要用另外两条去补第三条的说服力**。

## 反例

- 编造 tags / 编造 IoU 数字
- 用 24px 截图论证 16px 结论
- 「业界常用」「大家都这么做」当规范依据
- 只给正确率不给错误答案
- 把启发式阈值说成硬标准
- 灰度检查用彩色截图代替

## 自检

- 每条结论都能指到 `file:line` 或数字
- 度量给了口径（尺寸、描边、采样）
- 明确的「未验证」出现在该出现的地方
- 盲测门槛与错误记录都在

# 编排层：过程型状态机动效

本文件是 `motion.md` 之上的**编排层**，不是第七种形态。六形态回答「这一个图标该不该动、怎么动」；编排层回答「多个相位怎么串成一次过程、怎么停、怎么回落」。两层关系：每个相位内部复用六形态词汇（见 §二映射表），编排层只管相位之间的事件、时序、中断与回落。

判据与参数锚点来自一次真实 React 项目的三段状态机实现（五相位、420ms 触发轻推、1.5s/3s 停留、回落分叉、六个页面接入）；出处与本轮 round-trip 验证记录见本仓 `docs/.ai/decision-log.md` 与技能 CHANGELOG。项目是否批准编排、相位命名、停留参数一律由 profile 的 `motion.state_machine` 块承载（见 §八）；未批准的只进报告，不写成规则。

## 一、适用判据（准入）

三条全中才考虑编排，任一不中退回 `motion.md` 判静态或单形态：

1. **真实异步**：点击后要等一个真任务返回（请求/扫描/安装），不是本地同步逻辑。
2. **成败可判**：任务有明确成功/失败分支，且成败判定口径已定义（见 §四——多部分任务谁来定 done/error）。
3. **用户盯着等**：结果会改变这枚按钮或其所在行的状态，用户需要看到过程。

### 不该用的清单

| 场景 | 原因 | 代替 |
| --- | --- | --- |
| 纯开关（启用 / 收藏 / 筛选） | 布尔态无过程，乐观本地生效即可 | 静态色切换 |
| 纯导航 / 打开面板 | 无异步、无成败 | 无动效 |
| 两段式确认的**第一段** | 确认本身不耗时 | armed 样式（不是相位） |
| 本地秒完成的刷新 | 无「等」可言 | 单形态旋转（加载图标自转已够） |
| 先出计划再执行 | 耗时在第二段 | 状态机挂在执行段，第一段静态 |
| 全局进度 / 骨架屏职责 | 已有全局机制承载 | 不给单枚图标加编排 |

## 二、相位语法与形态映射

五相位是参考实现收敛出的最小集；项目可增删相位，但 idle 与回落语义必须存在。

| 相位 | 进入事件 | 表达 | 归入形态 | 禁止与误读 |
| --- | --- | --- | --- | --- |
| idle | 初始 / 回落 | 静止图标 | 静态 | 回落目标可被分叉改写（见 §四），不是永远同一枚 |
| burst | 点击 | 图标本体一次性微位移（轻推 2px 级） | 触发确认：语法借自抖动（一次性位移），但目标与语义不同——抖动=输入被拒，burst=点击被收到 | 与校验失败抖动共用同一图标；位移大于热区尺度 |
| sync | burst 结束且任务运行中 | loader 旋转（linear / infinite） | 旋转 | 已知进度用进度条；sync 必须伴 disabled 与 `aria-busy` |
| done | 任务成功 | 结论色静态图标 + 停留 | **静态色切换，不是动画**（不做描边——颜色就是结论） | 把停留当动画参数；描边绘制是六形态独立选项，不属相位默认 |
| error | 任务失败 | 结论色静态图标 + 停留 | 同上 | 只换色不抖；抖动只留给输入校验 |

两条设计原则：

- **动画只给「过程无信息」的相位**：burst（点到了）与 sync（正在跑）才动；done / error 是「有结论」的相位，用静态色表达，唯一的时间维度是驻留（hold）。
- **停留时长是状态机参数，不是动画时长**：done 停留给「看清结论」，error 停留给「读原因」。proposal 锚点：成功约 1.5s、失败约 3s（来自参考实现）；有令牌一律用令牌，无令牌标 proposal。

## 三、中断与重入

| 情形 | 参考语义 | 人判要点 |
| --- | --- | --- |
| sync / burst 中再点同一枚 | 按钮 disabled（busy 相位挡住） | disabled 矩阵覆盖**所有** busy 相位 |
| done / error 停留中再点 | 允许：清旧定时器、整体重启 | 停留态不 disabled，重试是合法路径 |
| 同 key 重入 | restart：取消未决定时器从头跑 | 不得排队、不得双跑 |
| 异 key 并发 | 互不影响（per-key 独立） | 同屏并发预算见 §五 |
| 组件卸载 | 清全部定时器 | 定时器泄漏 = 状态机实现坏 |
| 停留中列表数据刷新 | 相位不变，直到回落 | 回落以真实任务结算为准，不跟渲染走 |

## 四、停留、回落与分叉

- **回落（settle）是独立事件**：完成态停留结束、真正回 idle 那一刻才结算，不在 done 开始时结算——保证停留期间界面文字不被提前换掉。
- 回落可以**分叉**：按结果改写下一个静止态（如「检查」→ 查到更新 → 回落成「更新 N」；无更新 → 回落回自己）。分叉是静止态改写，不是新相位。
- 同一枚按钮的多个静止态**共用同一 key 的相位**：状态机只有一条，静止态是它的参数；两个静止态在同一时刻只呈现一个。
- **成败判定口径必须显式**：多部分任务要写清谁定 done/error。参考实现取「全失败才算失败」（部分成功即 done）；口径不写清，error 相位语义不成立，这条是编排层独有的必填项。

## 五、per-key 与同屏预算

- **每实例至多一个循环**：loader 只出现在被点的那一枚上，静止态永不自带循环。
- 行内多实例（每行一枚）允许并发、各转各的；**全局并发上限**由 profile `budget.max_primary` 决定。参考实现未设全局上限——要不要设，审查时按页面性质人判并登记。
- `motion.md` 的「同屏最多一个呼吸」是**全局**约束；编排层的循环预算是**每实例**约束，两者不互相替代。

## 六、aria 与静态可读

- 相位联动三件套：`aria-busy` 只在 sync；aria-label 随相位换文案（「…中」「上次失败，点击重试」——同一处口径供 aria 与 Tooltip 共用，避免两处写反）；busy 相位 disabled。
- 静止态与失败态必须脱离动画可读：图标语义、颜色、文字、`aria-*` 至少一组独立编码。状态本身不承载信息——动画只是把「正在发生什么」放慢给人看。
- reduce 降级**按相位**关动画（burst 位移、sync 旋转），结论链保留：成功绿勾、失败红警、文案照常。降级掉的是过程表达，不是结论。

## 七、审查清单（编排层 10 项）

形态与语义仍按 `motion.md` 审查；编排类实现（有相位状态机特征）额外查：

1. 适用判据三条是否全中；不中却用了编排 → blocker
2. 相位命名与事件链是否完整（idle 与回落必须存在；每个非 idle 相位有明确进入事件）
3. 停留时长是否来自令牌或 profile；裸值只标 proposal
4. 中断矩阵：重入语义（restart / ignore）是否实现且一致；卸载是否清定时器
5. 回落分叉：分叉条件是否真实、回落目标是否明确；有分叉需求却写死单回落 → major
6. 成败判定口径是否显式（多部分任务的 done / error 归属）
7. disabled 矩阵：busy 相位是否全部不可点
8. aria 三件套是否随相位联动
9. 循环预算：每实例至多一个循环；全局并发是否需要上限（需要而未设 → 登记待裁决）
10. reduce：按相位降级且结论链保留

严重度沿用 `motion.md`：语义误读 blocker / 预算令牌违约 major / 一致性 minor / 源码不足 `N/A` / 不可运行时验证 `needs-review`。

## 八、profile 承载

编排规则进 `motion.state_machine` 块（可选；无此块 = 项目未批准编排，只出建议）。字段说明见 `templates/profile.example.yaml` 的对应注释。要点：

- `phases` 相位白名单；项目自定义相位命名时同步 §二映射表
- `hold.done_ms` / `hold.error_ms` 只引用令牌；无令牌标 proposal
- `reentry: restart | ignore`；`settle_fork` 是否批准回落分叉
- `loop_budget: per-instance` 是默认且必须；全局并发上限用 `motion.budget.max_primary`
- 打断、同屏并发、成败口径等语义条款进 `human_checks`

## 九、机检与人判的边界

能静态查的（后续批次落机器）：`is-{phase}` 一类类名序列完整、多枚图标同槽只切 opacity、按钮宽度不变、`aria-busy` 随相位、reduce 下相位动画关闭。查不了仍 `human_check`：真实任务生命周期、成败判定口径、分叉正确性。

## 自检

- 先过适用判据，再谈相位；不该用清单逐条排除过
- 每个非 idle 相位有事件、有参数来源、有 reduce 替代
- 中断矩阵与卸载清理都写了；重入语义明确
- 回落与分叉的结算时机正确（回落时，非 done 开始时）
- 成败判定口径显式；循环预算按实例计，与 `motion.md` 全局约束不混淆
- 未批准编排只进报告，不写进 profile

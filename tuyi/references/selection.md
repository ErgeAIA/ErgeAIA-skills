# 选型

选型的目标不是「找一个好看的图标」，而是**让目标读者在 16px 下一眼读出正确的那一个意思，并且不会误读成同排的其他意思**。

## 第 0 步：先要信息，不要先给答案

开始检索前，确认三件事（缺哪件就按缺的那件处理，不要假设）：

1. **徽章要表达什么**（原话即可，不要先翻译成英文）
2. **它出现在哪**（表格行、工具条、详情页头部、卡片角标——决定尺寸与同排邻居）
3. **有没有既有规范/既有映射**（有 profile 就读 profile；没有则问一次，再走轻量抽取）

如果用户只给了一个词（如「本地」），先做槽位判定，再把判定结果用一句话回报：「按来源槽处理，16px 纯图标 + Tooltip，不加边框——如果它其实是判定结论，告诉我，结论槽要用状态色。」

## 第 1 步：判槽位

按 `slot-model.md` 的判定顺序走。输出一行结论：

```
槽位=来源 | 形态=纯图标 | 尺寸=16 | 色=text-muted | Tooltip=必填 | 可点=否
```

## 第 2 步：查既有映射

- profile 里 `mappings` 有 `status: locked` 的同义项 → **直接返回它**，不重挑。重挑的代价是同一概念出现两种图形，用户的肌肉记忆作废。
- 有同槽位但不同义的项 → 记下来，作为第 4 步的「同族混淆」参照。
- 没有 profile → 跳到第 3 步，并在输出里说明「无既有映射可比对」。

## 第 3 步：检索候选

用脚本检索，不靠记忆：

```bash
PYTHONIOENCODING=utf-8 uv run --no-project python scripts/iconlab.py search --query "本地 离线 安装来源" --slot source --top 12
```

检索策略（按优先级）：

1. **意图词而非直译词**：「本地」不要只搜 `local`，要搜 `local, offline, disk, storage, hard-drive, install, manual`——真正贴切的往往是「物」而不是「概念」。
2. **槽位过滤**：来源槽偏好「物体/介质」名词（disk、drive、package、box、globe）；动作槽偏好「动词性」图形（open、copy、move、trash）；状态槽偏好「判定性」图形（check、x、warning、question、clock）。
3. **至少留 3 个候选**，其中必须包含一个「明显不对但常被想到」的候选（如 `unlink`），因为排除它本身是结论的一部分。
4. **记录命中词**：每个候选后面写清它是因为哪个 tag 被召回——这是证据，也是复核入口。

候选池不足 3 个时，放宽到同类词（同义/上下位），并在输出里注明「放宽后的召回」，不要硬凑。

## 第 4 步：四类排除

按顺序过，每类给一句判词：

| 排除类 | 判据 | 例子 |
| --- | --- | --- |
| **借用错误语义** | 图标的字面义暗示了错误的状态/情绪 | `unlink`/`cloud-off` 表达「本地」→ 读成断连、断网 |
| **动作/状态错位** | 图形是动词性的，却放在状态位 | `download`/`folder-input` 放在「未安装」→ 读成「去下载/去导入」 |
| **同族轮廓混淆** | 与同排既有图标在 16px 下剪影近似（IoU 高）或属于同一视觉族 | `folder-input` 与移动/导入族；`package` 与 `package-open`/`package-plus` 三兄弟 |
| **风格/许可不合** | 混入另一套线型、混用付费图标集、与 profile 的 `icon_library` 不一致 | 同组控件里 Lucide 与实心图标混用 |

判定「同族轮廓混淆」要有数：跑 `iconlab.py measure`，看 16px IoU 与 ink ratio。**IoU > 0.75 视为高混淆**，必须在推荐里点名，并给出差异化手段（换图形、加 Tooltip 文案区分、或改布局拉开距离）。

## 第 5 步：给结论

输出三档，缺一不可：

- **首选**：一句话说清它为什么对——优先说「它对应的是哪个具体物/动作」，而不是「它很常见」。
- **备选 1 个**：说清它在什么条件下更好、代价是什么。
- **明确不建议**：至少 1 个，写清被排除的原因（这是让用户信任结论的关键，也是最容易被省略的部分）。

推荐话术模板（照这个结构写，别写成散文）：

```
槽位：来源（事实，不是判定）
首选：hard-drive —— 对应「本机磁盘上的东西」，直接回答「不是从远端仓库装的」；横向扁矩形，与操作列的 git-fork / external-link 剪影差异大（16px IoU 0.29）。
备选：package-open —— 若该列表同时存在「仓库/包」概念，它能和 package-plus（安装）形成同族对照；代价是 package 家族三兄弟在 16px 下易混。
不建议：unlink / cloud-off（借用断连语义，正常状态被读成故障）；folder-input（动词性 + 与导入/移动族同形，状态位会读成动作）。
```

## 第 6 步：动效判定（条件）

只有场景涉及**真实状态变化、任务过程或操作反馈**时才做；纯静态状态、来源标记、收藏、普通按钮一律写「静态，不建议添加」。先回答四个问题，任一答「否」就停在静态：

1. 有没有真实的状态变化或任务过程？
2. 有没有明确的停止条件（完成/失败/取消/卸载）？
3. 静态等价（换图形、换色、加文字、Tooltip）能不能表达？
4. 项目当前是否允许动效落地（读 profile 的 `motion`）？

结论必填 7 字段：

```
动效结论：静态 / 旋转 / 脉冲 / 扫描线 / 呼吸 / 描边绘制 / 抖动 / 待裁决
动画目标：整枚图标 / SVG 子路径 / 输入容器
语义与触发：<真实事件>
参数来源：<项目令牌>；无令牌则标 proposal
停止条件：<完成/失败/取消/卸载>
reduce 替代：<静态忙碌图标 + 文字 / aria-busy / 即时显示>
项目允许性：<profile 状态 + source_ref；未批准写 pending>
```

禁止为了字段完整给每个图标硬填动画；裸毫秒只能作为 proposal，不能写成规则。六形态的语义、禁忌与技术边界见 `motion.md`。

## 歧义：停下的条件与三问

🔴 **CHECKPOINT · 🛑 STOP**——**可计算阈值**：首选与次选的分差 < 20%，且首选在 16px 下与某个同排邻居 IoU > 0.75 → 停，不许自选。

固定三问（原样问，别改写成开放式问题）：

1. 「这个标记是**结论**（对错/缺失/待定）还是**事实**（来源/类型/属性）？」
2. 「它需要**扫视一眼就看到**，还是悬浮/点开知道就够？」
3. 「同一排里，还有哪几个图标可能被读成它？」

三个答案合起来通常直接落到某个槽位或梯子档位。若仍落不下来，输出两案并列：

```
A 案：纯图标 + Tooltip（更安静，但必须悬浮才知道）
B 案：图标 + 短词（一眼可读，但会与同排状态图标争注意力）
代价：A 的隐藏成本是……；B 的隐藏成本是……
请选择，或告诉我这两个信息里哪个更常被用到。
```

## 自检

- 候选 ≥ 3，且每个都有命中 tag
- 每个不建议者都有具体排除理由（不是「不合适」）
- IoU 数字给了，没说「差不多」
- 有 profile 时没有重挑 locked 项
- 歧义触发时确实停下了
- 动效先给了静态结论；没有为凑字段给静态图标填动画
- 有动效时写清真实触发、目标、停止与令牌来源；无令牌只标 proposal

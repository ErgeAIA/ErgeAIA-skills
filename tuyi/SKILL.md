# 图意 · Tuyi

> 图意者，辨图之所指，定其位而择其形。徽章之选，先明其意，而后取象。

## 定位

把"这个徽章该用什么图标"从审美偏好，变成一套可以复核的判定：**槽位决定形态，图标库决定候选，度量决定排除，证据决定结论**。

本技能选图标、不画图标；做审查、不替用户改产品；**歧义未解时停下对齐**，不靠猜。

## 何时使用

- 要一个徽章图标：状态位、来源标记、计数、筛选开关、行内动作、导航项
- 已有徽章系统/图标用法要审查：文字胶囊滥用、图标混用、缺 Tooltip、热区过小、判定色乱用
- 在"图标 + Tooltip"和"带文字胶囊"之间拿不准
- 想从设计规范里抽出可执行的图标规则，供后续复用

Not for：需要新画定制图标（本技能只从真实图标库中选）；纯排版/间距/字体问题；icon font 打包与构建链路；脱离设计规范的一次性审美比稿。

## 三条铁律

1. **先判槽位，再谈图标**。同一个图形在不同槽位里意思不同——`link-2` 在"共享引用"是状态，在"定位库"是动作。槽位判错，后面全错。
2. **既有映射优先，不重挑**。规范里已锁定的映射（本地=`hard-drive`、缺失=`file-x`）直接沿用；重新选择=制造两套语言。
3. **证据不足就停下**。候选必须来自真实图标库的 tags；结论必须带出处与度量；有歧义先按「三问」对齐，不猜。

## 模式路由

| 模式 | 触发信号 | 主场文件 |
| --- | --- | --- |
| **A 选型** | 要一个具体徽章图标，或在几个候选间犹豫 | `references/selection.md` |
| **B 审查** | 已有徽章系统/一批图标用法要挑错、要优化意见 | `references/review.md` |
| **C 建 profile** | 要把一份设计规范变成可执行的图标规则 | `references/profile.md` |

三种模式共用同一套底座：槽位（本文件 + `references/slot-model.md`）与证据（`references/evidence.md`）。审查模式额外需要一份 profile；没有 profile 时先走 C 的轻量版（`references/profile.md` 的「快速抽取」）。

动效不是第四种模式：它是 A/B 的条件分支，项目动效规则由 C 产出的 profile 承载，判据见 `references/motion.md`。

## 底座：六个槽位

任何徽章先归槽，槽位决定它的形态、尺寸、颜色、要不要 Tooltip、能不能点。

| 槽位 | 回答的问题 | 默认形态 | 允许文字 | 可点 |
| --- | --- | --- | --- | --- |
| **状态** | 结论是什么（对/错/待定/缺失） | 纯图标 + Tooltip | 否 | 否 |
| **来源** | 它从哪来（本地/仓库/外部） | 纯图标 + Tooltip | 否 | 否 |
| **计数** | 有几个 | 图标 + 外侧数字 | 是（仅数字） | 视场景 |
| **筛选** | 是否按这个条件看 | 纯图标，开合态只改色 | 否 | 是 |
| **动作** | 点一下会发生什么 | 纯图标按钮 + Tooltip | 否 | 是 |
| **导航** | 会去哪 | 图标（+可选标签） | 可选 | 是 |

判槽位只问两件事：**这是事实还是结论？**（来源/状态的分界）**点它会不会发生事？**（动作/状态的分界）。判定细则、每槽的禁忌与反例见 `references/slot-model.md`。

## 判定梯子：什么时候根本不该用图标

不是所有徽章都适合图标。从信息强度往下退：

1. **纯图标 + 主题化 Tooltip**——含义离散、可穷举、同排不混淆（默认档）
2. **图标 + 短词**——需要扫视即懂，或同排存在近形图标
3. **纯文字胶囊**——含义是连续量、需要比较、或词本身比任何图形都准（"缺 1""待 48 小时"）
4. **换表述**——以上都别扭，说明这个信息不该做成徽章（写进详情、合并进别的列）

退出条件（命中任一就别硬套图标）：含义无法用单个名词概括；数值需要精确比较；需要常显才能做决策的信息（Tooltip 是隐藏信息，不能承载它）；同排已有三个以上图标且都在同一视觉重量上。

## 选型五步（模式 A）

1. **判槽位**：按上表定性，写下形态/尺寸/色令牌/是否 Tooltip
2. **查既有映射**：profile 里 status 为 locked 的直接返回；不得重新发明
3. **检索候选**：`scripts/iconlab.py search` 从真实目录的 tags 检索，至少 3 个候选；不给"凭印象"的答案
4. **排除**：借用错误语义 / 指向动作却放在状态位 / 同族轮廓混淆 / 许可或风格不合
5. **给结论**：首选 + 1 个备选 + 明确不建议者（附各自被排除的理由）

每步的判据、排除项清单与证据模板见 `references/selection.md`。

**第 6 步（条件）：动效判定**。只有场景涉及真实状态变化、任务过程或操作反馈时才做；否则结论是「静态，不建议添加」。先问四件事：有没有真实变化、有没有停止条件、静态能不能表达、项目当前是否允许落地。结论必填 7 字段（形态/目标/语义与触发/参数来源/停止/reduce/项目允许性），判据见 `references/motion.md`。

## 歧义：停下的条件与三问

🔴 **CHECKPOINT · 🛑 STOP**——**阈值**（可计算）：前两名候选的意图匹配分差 < 20%，且存在与首选 16px 轮廓 IoU > 0.75 的近邻 → 不许自选，停下来问。

固定三问（问法不要改写，用户能快速答）：

1. 这个标记是**结论**（对错/缺失）还是**事实**（来源/属性）？
2. 它需要**扫视时就看到**，还是悬浮/点开才知道就够？
3. 同一排里，还有哪几个图标可能被读成它？

答案能落到槽位或梯子档位就继续；落不下来则输出「两案并列 + 各自代价」，交给用户拍板。

## 审查三步（模式 B）

1. **取规则**：读 profile（条款带 `file:line`、槽位、锁定映射、待裁决冲突）
2. **跑机器检查**：`scripts/badge_lint.py --profile ... --target ...`，拿 `file:line` 级 findings
3. **补人判**：机器查"形态对不对"，人判"语义对不对"（槽位错配、图标借用错误语义、同排混淆）

报告结构、严重度口径、误报控制见 `references/review.md`。

4. **动效审查**：在形态与语义之外，查是否有真实触发、是否正确目标、是否完成即停、是否超预算、是否用项目令牌、reduce 是否降级、静态时是否仍可理解。运行时语义 `badge_lint.py` 查不了，按 `references/motion.md` 的 9 项人判；源码不足标 `N/A`，无法运行时验证标 `needs-review`。

## 渲染页（每次选型必出）

结论必须配一张离线单页 HTML：真实尺寸阶梯（12/16/18/20/24）、双主题、灰度版、真实行上下文、候选对比、混淆矩阵、可复制规格块。

```bash
PYTHONIOENCODING=utf-8 uv run --no-project python scripts/iconlab.py render --case case.yaml --out badge.html
```

规格与验收见 `references/render.md`；case 结构见 `templates/case.example.yaml`。

## 输出契约

**选型卡**（模式 A）必含 8 项：槽位判定 / 首选与理由 / 备选与代价 / 不建议者与被排除原因 / 三段证据 / 歧义处理 / 渲染页路径 / 动效结论（静态须明确写「不建议添加」；有动效则给 7 字段）。

**审查报告**（模式 B）必含 7 项：profile 与来源 / findings（`file:line`+条款+严重度+最小改法）/ 已合规清单 / N/A 清单 / 待裁决冲突 / 动效 findings（静态/形态/待裁决 + 触发、停止、reduce）/ 结论。

**任何结论都要能落到三类证据之一**：规范原句（`文件:行`）、图标库事实（id + tags + 许可 + 版本）、视觉度量（16px 轮廓 IoU / 墨量比 / 行上下文并排）。给不出就标"未验证"，不许编。

## 验收清单（交付前逐条自检）

- [ ] 槽位判定有依据，不是"看起来像"
- [ ] 候选来自真实 tags 检索，附 id 与命中词
- [ ] 已锁定的既有映射未被重挑
- [ ] 每条理由都有 `file:line` 或度量数字
- [ ] 给了 16px 轮廓 IoU 与同排行上下文
- [ ] 有歧义时已按三问对齐，或明确标注了假设
- [ ] 渲染页：1440×950 无横向溢出、双主题、颜色全部来自变量、离线可开
- [ ] 审查报告：每条 finding 有 `file:line` + 条款 + 最小改法；N/A 与 pending 冲突未被伪装成"通过"
- [ ] 机器检查的 `passed` 已逐条确认真被检查；解析失败或无法静态判定的条目在 `unchecked` 里，未计入 `passed`
- [ ] 动效先给了静态结论；没有为「字段完整」给每个图标填动画参数
- [ ] 有动效时写清真实触发、目标、停止条件与项目令牌来源；无令牌只标 proposal
- [ ] reduce 降级与静态等价已写；运行时验证有真实结果，或明确标 `needs-review` 并说明边界

## 失败模式与兜底

| 失败 | 兜底 |
| --- | --- |
| `badge_lint` 把某条规则列入 `unchecked`（开标签/内联 style 无法静态判定、内文含动态表达式） | 必须人判复核该规则，并在报告里点名「此项未检查，不计通过」；不得只凭 `passed` 写 PASS |
| `badge_lint` exit 2（用法/解析/目标错误） | 先修参数或路径再判；不得当作"检出问题" |
| 候选 `< 3`，或 16px IoU 不可算（图标路径解析失败） | 扩检索词；仍不足或不可算就标"未验证"，不得把未验证候选当首选 |
| `iconlab render` 失败 | 降级为文字规格并标"渲染未验证"；不得声称已渲染 |
| profile 缺失，或冲突仍为 `pending` | 按 `references/profile.md` 做轻量抽取；冲突按 interim 执行并在报告点名，不能静默选一边 |
| 动效无法运行时验证（无浏览器/无真实交互） | 标 `needs-review` 并给手工验证清单，不得写「已通过」；不能只凭 `prefers-reduced-motion` 文本存在就判降级生效 |
| SVG 子路径不可稳定定位，或图标库版本与项目安装版本不一致 | 建议静态；跨版本路径结论标「未验证」，不写「大概可以」 |

机器检查与人判的分工见 `references/review.md`。

## Gotchas

- **图标字面义 ≠ 使用义**：`unlink` 字面是"取消链接"，用来说"本地插件"就变成"连接断了"；错的是槽位语义，不是图形本身。
- **中英断裂**：Lucide 的 tags 是英文，用户说的"本地"直译成 local 会漏掉 hard-drive/disk 这些真正贴切的候选——用 `iconlab.py search` 的意图别名词表，不要手翻。
- **16px 才是考场**：24px 好看的图标在 16px 可能糊成一团，判定一律以 16px（或该槽位声明的尺寸）的剪影与行上下文为准。
- **Tooltip 不是垃圾桶**：把必须常显才能决策的信息塞进 Tooltip，等于让用户逐个悬浮。
